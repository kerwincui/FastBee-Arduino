# G02：共享 SPI 所有权与生命周期实施检查单

状态：20261001 批次，SD 与 RFID 租约候选已分别通过 Host/Native/九目标及归档；通用 SPI 稳定逻辑 ID 和事务锁增量本地 30/30 通过，详见第 8 节，新候选完整门禁另记。SPI TFT、W5500 和资源规划一致性尚未闭环，不是 G02 完成或硬件支持声明。设备仍为原部署 r2，不包含这些后续 SPI 改动。入口见 `system-improvement-execution-20261001.md`。

## 1. 已核实的调用链

| 使用方 | 当前初始化与 I/O | 当前退出与风险 |
| --- | --- | --- |
| 通用 SPI 外设 | 按逻辑 ID acquireNamed 持有实际租约，I/O 在管理器锁后取 SPI 操作锁并核验 owner/句柄/引脚，再进入 Arduino 事务 | 只释放自己的租约及确认独占的 CS；忙锁保留，host 暂不自动关闭，W5500 仍待协调 |
| SDSPI 存储 | 经 acquire(this, pins) 持有实际租约，存储互斥后再取总线操作锁，文件操作结束才释放操作锁 | 三类挂载后失败关闭 SD 层并释放自己的租约；硬件总线暂保留，避免误停未纳入登记的 W5500/旧使用方 |
| MFRC522 | 单例 acquire(this)；初始化/读写/停止共用操作锁，轮询和状态快照不等待忙锁 | 缺 reader 回收自身租约；stop BUSY 保留 reader/租约/引脚，事件在解锁后派发；硬件 host 仍保守保留 |
| SPI TFT | `SpiTftDisplayBackend.cpp` 使用同一个全局 SPI，初始 MISO=-1；事务内发送像素 | end 故意不调 SPI.end 以保留其它使用方，但没有最后使用方退出的统一资源回收 |
| W5500 | `EthernetAdapter.cpp` 自建 SPIClass；新核心走 ETH.begin，旧核心回退 IDF SPI | 独立 C++ 对象不自动证明独立硬件 host；需与芯片能力和规划器对齐，不能盲目与全局 SPI 合并 |

本机已安装 Arduino 核心的 `libraries/SPI/src/SPI.cpp` 显示：`begin()` 在 `_spi` 已存在时直接返回 true，不重新附加 MISO/切换引脚；`end()` 解除 SCK/MISO/MOSI。故“重复 begin 即自动协调多个模块”不成立。当前 `PeripheralResourcePlanner.cpp` 的 `samePins()` 对三根总线脚逐一完全比较，TFT 的 MISO 为 BOARD_PIN_NONE，因此通过当前预检的普通流程会拒绝其与有 MISO 使用方的组合；不能把这个受限组合表述为已支持共存。启动旧配置/未经过预检的入口仍需核验，以上不作为已发生现场故障。

## 2. 推荐实现边界

1. 延用既有 `PeripheralResourcePlanner` 引脚角色、共享总线和 CS 冲突规则，不另建一套 Web 规则；先补通用 SPI 相互释放的最小回归，再收口全部实际使用方。
2. 总线所有权按硬件 host + 引脚组明确登记，采用固定容量 owner 表；兼容性检查、首次启动、最后释放均在相同互斥下。先检查兼容再动引脚，失败不得破坏已有使用方。
3. 配置 owner 与成功运行实例分开：enabled 不是已持有租约的证明；失败/重配/删除都只释放自己持有的资源。对象析构不得留下指向释放内存的 token。
4. 明确锁顺序和有限等待。driver 外层锁与 SPI transaction 锁不递归反转，停止等待正在进行的传输；超时返回可诊断的 BUSY，不盲目 end/重试写动作。
5. 只写 TFT 与全双工设备的共存要么在首次创建时完整配置实际总线引脚，要么明确拒绝需要重绑的新增组合并提示重启；不能在其它使用方活跃时重新初始化整个 host。
6. W5500 涉及 IDF/Arduino 两条路径，单独验证 host、任务停止、回调注销和失败回滚；在证据不足前标条件支持，不为了通过测试全局禁用网络功能。
7. 不改现场配置来掩盖冲突，不自动测试电机/继电器等输出，不把“SPI 支持”泛化为“任意 SPI 芯片已有驱动”。

## 4. 首批修复与明确剩余项

新增 `SpiBusTeardownPolicy.h`，通用 SPI 退出时保守检查其它启用的通用 SPI、MFRC522、SDSPI 和 spi_tft。由于这些路径使用同一个全局 SPI 对象，引脚声明不同、TFT 缺 MISO 或旧配置不完整均不能作为独立总线的证明；存在这些配置时不调用 SPI.end。SDMMC、RGB 面板、I²C 不被算作全局 SPI。旧配置 CS 冲突时也不把另一使用方的 CS 改为输入，新增配置的资源冲突预检仍保留。

`test_spi_teardown_policy.py` 两项（生产 C++ 策略及调用接线合同）、生命周期合同 10 项、板卡资源规划 3 项通过。C++ 覆盖四种使用方、启停/自身排除、不同引脚、无效配置、同 CS，以及 1000 次无残留策略评估；这里的 1000 次不是实物 SPI 操作或长稳验收。

这是对现有配置级 teardown 的最小安全修复，不伪装统一所有权已完成：enabled 仍不证明持有运行租约，失败初始化仍可能保守保留总线。后续必须实现固定容量实际租约、初始化失败释放、事务期间退出、TFT/全双工顺序、RFID/SD/TFT 自身停止路径，以及 W5500 硬件 host 协调。没有据此放宽规划器或宣称任意 SPI 设备可以共存。

## 5. 第二批：可检查的初始化与局部失败回滚

本机固定 Arduino SPI 实现的另一个失败边界已经核实：pin attach 返回 false 时没有调用 end，bus() 可能仍非空，下一次 begin 又会因非空直接返回 true。之前通用 SPI、SDSPI、MFRC522、SPI TFT 四条路径均忽略 begin 的返回值，可能继续驱动设备或报告初始化成功。这是代码路径证据，不是对现场传输失败的根因诊断。

新增 SpiBusInitializer，只负责全局 SPI 对象的 begin/end 检查，不负责运行租约：

- 懒创建一次互斥，初始化竞争采用原子发布，释放未发布的多余互斥；等待最多 1000ms。无外设实例时不主动创建锁。
- 缓存成功实际申请的 SCK/MISO/MOSI；已启动总线不能静默换脚，未知来源的活跃 SPI 拒绝接管/关闭。CS 仍是各设备独立资源，冲突由已有规划器负责。
- 首次底层 begin 失败只清理这次新创建的总线；已有共享总线在不兼容申请、互斥超时或设备后续失败时不被关闭。
- 通用 SPI/SD/TFT 在初始化返回成功之后才设置专属 GPIO；RFID 在通信前检查返回值并释放失败 reader，补 nothrow 分配失败及部分显式引脚拒绝。RFID 全默认组合采用板级 SCK/MISO/MOSI 定义，不新猜接线。
- 通用 teardown 经已有保守保护后再请求受锁保护的 end；BUSY/未知总线时返回失败，保留总线与 CS，不伪称已经释放。

输入脚顺序仍有明确限制：先有全双工总线时只写请求可以复用，先有 MISO=-1 的只写总线时新增有 MISO 的设备被拒绝，不动态重绑。规划器仍按原完整 pin tuple 预检，因此该运行时防线不意味着 Web 中已开放 TFT/全双工混用。

## 6. 第三批：固定容量租约与 SD 接入（后续候选）

本节更新第 5 节中 SD 的未完成部分；RFID、SPI TFT、通用 SPI 和 W5500 的剩余边界没有因此关闭。选择 SD 作为第一个完整接入方，是因为其单例 owner 生命周期稳定且已有存储互斥；通用外设配置对象存在复制/删除路径，不能直接把临时配置地址当成永久 token。

### 租约与操作锁

- 在原初始化器中加入固定 16 个 owner/CS 槽、重复申请幂等、改变 owner 的 CS 需先释放、已登记 CS 冲突拒绝、容量耗尽提前拒绝。只有底层成功后登记，不使用无界 map。
- 初始化锁改为递归互斥；锁序为设备自身互斥 → SPI 操作锁 → Arduino SPI 事务。SD 的挂载、配置、卸载、容量读取和四种文件操作全程受保护，失败/提前返回通过 RAII 释放操作锁。
- 原始 end 不再允许关闭仍有租约的总线；有操作在途时按原 1000ms 上限返回 BUSY。失败 release 保留 owner，不能伪造已释放。
- 即使最后一个已迁移 owner 释放，也暂不自动调用 SPI.end。核实 W5500 的独立 SPIClass 仍可能使用同一硬件 host，未完成双向协调前，新的 SD 卸载不能引入误停网络的行为。显式 end 仍须由调用方先确认所有使用方停止，并会拒绝活动租约；自动最后退出硬件回收仍是未完成项。
- 固定表属于静态存储，互斥懒创建且保留复用；不能说无实例时完全零 RAM 或把减少重复分配等同实测 RAM 收益。构建及真实峰值仍另测。

### SD 的完整失败路径

底层 begin 失败不登记 owner；SD.begin 失败、无卡、沙箱目录创建失败先关闭本次 SD 层，再释放自己的租约。正常卸载可保留配置以便后续重挂，错误 owner 不得卸载别人；重配在同一锁内停止旧挂载并释放旧租约。原沙箱、16KiB 文件和 32 项列表上限不改。CS 保持原有未选中策略，没有声称所有专属 GPIO 都已经释放。

SD 自身互斥的首次并发创建改为原子发布，竞争失败者销毁多余句柄。若硬件 handle 被外部代码丢失，读写和容量查询返回 SD_SPI_LEASE_LOST，不在仍有租约时偷偷重建总线；需按明确卸载/恢复流程处理。此项是主机故障注入，不是现场断线自愈验证。

## 7. 第四批：RFID 实际租约、停止互斥与诊断快照

RFID 单例继 SD 后接入固定 owner 表，begin 成功申请才探测芯片，分配/初始化/版本寄存器异常均按自身所有权清理。反复 begin 相同配置幂等，不同 CS/RST/总线脚返回 RFID_CONFIG_CHANGED，不能把旧实例当成新配置成功；默认总线脚只取编译板型常量，不再误写成通用 S3 接线。

- 初始化、选卡、认证、读块、写入/回读与 stop 都持有同一个总线操作锁。不额外增加 RFID 堆互斥；锁等待有界，但底层卡片 I/O 总时长不是硬实时承诺。
- stop 改为可失败接口；PeripheralManager 必须先确认停止成功，再释放 SS/RST。操作超时不删除 reader、不释放租约、不改变专属引脚，并向运行状态保留错误。清理失败保留 reader 以供显式重试，不挂空指针 owner。
- 轮询以零等待取锁，忙时跳过本次检查，不阻塞主循环等待其它使用方。检测/移除事件先复制必要数据，完成 Halt/Crypto 清理并解锁后派发，允许规则重入存储/设备停止而不持有 SPI 锁。事件表示一次已完成的观察，不宣称派发时卡片仍然存在。
- HTTP 状态一次读取非阻塞一致快照；忙时 statusAvailable=false、driverError=SPI_BUSY，不输出伪造的初始化/UID 字段。Web 显示“忙碌，状态待刷新”，清空展示的 UID/卡型但保留用户块数据输入；不自动发起写卡或重启。
- 硬件句柄或租约丢失时拒绝扫描/读写，快照标明 RFID_SPI_LEASE_LOST；stop 只回收可确认的资源，不触失效句柄。不通过后台定时重启或强制关 host 掩盖故障。
- 原 MIFARE 数据块 1～62、禁止制造商/扇区尾块、Key A 认证、写后读回校验保持；没有扩张卡型支持或执行真实写卡。

## 8. 第五批：通用 SPI 稳定逻辑 ID 与事务保护

新增 PeripheralManagerSPI.cpp 承接原 setup/teardown 入口；外层仍由管理器持锁。按实际成功的逻辑 ID acquireNamed，inline key 限 1～40 字节、禁止内嵌 NUL，与 ResourceProfile 编译期断言对齐。固定 16 槽由命名 owner 与 SD/RFID 指针 owner 共用，重复 ID 相同配置幂等，不保留配置副本或临时 String 地址。改变 CS/总线脚/MISO 使用方式拒绝，原租约保留。

I/O 取得管理器锁后以 20ms 等待总线锁，checkNamed 确认 owner、底层句柄和原引脚元组，再进入事务。CS LOW → transfer → CS HIGH → endTransaction 均在操作锁内；空缓冲不通信，失败读取长度为 0，BUSY/缺失租约/配置改变/句柄丢失保存明确运行错误。频率为 0 延用 1MHz 默认约定；等待上限不能解释为完整硬件传输硬时限。

teardown 仅释放本 ID，且仅在确实释放并无配置级 CS 别名/其它运行占用时将自己的 CS 置输入。错误 CS 或忙锁不释放，不拆除未成功初始化对象所指的其它使用方引脚。当前仍保留底层 host，不从配置/租约表空推导 W5500 已停止。全部用户的双向 host 协调、运行换脚/回滚与 SPI TFT 生命周期仍待完成，未放宽资源规划器的现有共享限制。

## 9. 第六批：SPI TFT 租约和可确认的停止

更新前节中 TFT 尚未接入的边界；W5500 双向 host 协调仍未完成。TFT 的生产 backend 以其稳定实例地址取得 owner/CS 租约，操作锁覆盖初始化、绘制、背光、休眠和清理。没有有效租约或底层 handle 时不拉低 CS、不发起事务；初始化冲突和忙锁不改专属 GPIO。

- 初始化期间明确拒绝零尺寸和仍持有旧租约的重复配置。LEDC attach、初始亮度写入和控制器命令路径失败只清理自己的资源；SPI 写接口无硬件 ACK，不能由初始化命令发出推断显示器真实存在。
- 指针 owner 与逻辑 ID owner 对 MISO 使用方式保持一致：同 owner 从输入改成无 MISO 或反向改变都需先释放。不同 owner 仍沿用保守初始化顺序：已有 MISO 可加 write-only TFT，write-only 总线先启动后不能假装追加 MISO 已接通。
