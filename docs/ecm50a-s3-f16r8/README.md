# ECM50-A ESP32-S3-F16R8 配置

[返回配置样例索引](../README.md)

目标环境为 `esp32s3-F16R8`，本次目标串口为 COM15。这是 ECM50-A 专用工业采集配置，不能用于其他 S3 板卡或其他芯片。

## 当前状态（2026-09-22）

已按现场清单更新配置。温湿度参数已按 IVG-TH 文档核对，漏水与温湿度均已实际读通；其余 Modbus 单位、倍率和继电器指令仍需厂家协议或实物核对。MQTT 保持关闭，接入信息由用户后续填写。固件与配置的烧录结果见本文末尾验收记录。

## 引脚和外设

| 功能 | 外设 ID | GPIO |
| --- | --- | --- |
| A1：4-20mA 土壤水分 | `ai_soil_humidity` | 6 |
| A2：4-20mA 土壤温度 | `ai_soil_temp` | 7 |
| D1/DI1：光电黑线 NO；D2/DI2：白线 NC | `di1` / `di2` | 4 / 5 |
| 本板继电器输出 1 / 2 | `do1` / `do2` | 15 / 16 |
| Modbus RS485 | `rs485` | RX=18、TX=17 |
| 运行指示灯 | `run_led` | 21 |
| 可选 I2C 总线（禁用） | `i2c_sht30_bus` | SDA=1、SCL=2 |

A1 水分、A2 温度按当前传感器线序配置：黄色水分信号接 A1，蓝色温度信号接 A2。灯接本板继电器，保留 DO1、DO2 独立控制；实际使用哪一路仍需按接线选择。地址 6 的 Modbus 继电器是独立设备。

网络模板还定义 W5500（SCLK=12、MISO=13、MOSI=11、INT=14、CS=47、RST=48）和 EC801E-CN（TX=39、RX=40、PWRKEY=38）。本次部署保留设备现有网络和身份配置。RS485 使用模板的 9600、8-N-1、自动收发（`dePin=255`）。

## 土壤模拟量

每 10 秒采集两路 AI。输入范围 4–20mA，温度量程 **−40–80°C**，水分量程 **0–100%**，均保留一位小数，对应用户提供的 0.1°C / 0.1% 分辨率；该显示精度不等于板端实测精度。属性 ID 保留 `soil_temperature` 和 `soil_humidity`。

- 温度：`−40 + (I_mA − 4) × 120 / 16`。
- 水分：`(I_mA − 4) × 100 / 16`，单位 `%`。
- 模拟前端沿用 `shuntResistance=165`、`inputGain=1`、`inputOffset=0`、`vRef=3.3`；仍需与板上电路及标准电流源校准结果核对。
- 每次 16 次均值采样，`clampEnabled=false`；异常输入保留质量状态，不钳位为正常端点数据。

SHT30 不在本次现场清单中。沿用用户当前配置，SHT30 外设和 `s3_optional_sht30` 规则已删除，保留的 `i2c_sht30_bus` 禁用。

## 光电互补输入与故障事件

| D1（NO） | D2（NC） | 状态 |
| --- | --- | --- |
| 1 | 0 | 无物体 |
| 0 | 1 | 有物体 |
| 1 | 1 | 故障，包括所述断线或掉电情形 |
| 0 | 0 | 非法组合，按故障处理 |

两路为普通上拉 DI（`type=11`、`inputMode=2`、`invertLogic=false`），单路去抖 50ms。仅在 `di1.params` 配置 `pairedInputId="di2"`、`pairDebounceMs=200`。固件通过现有 100ms 输入检查任务采样，组合状态连续稳定 200ms 后确认；无法读取配对输入也按故障处理。Web 外设编辑可修改配对 ID 和确认时间。

每次持续故障只触发一次 `break_down` 设备故障事件，稳定恢复后重新允许下一次告警。MQTT 断开时只保留当前故障的待发状态，连接可用后发送；发送失败至少间隔 5 秒重试，发送成功后不重复。若故障已经恢复，则取消待发故障，不在重连后发送过期事件。待发状态保存在 RAM，重启后重新判断。

在光电联动规则 `s3_photoelectric_relay_toggle` 中，DI1 稳定从高电平变为低电平（有物体进入）时执行一次 `ACTION_GPIO_TOGGLE`，翻转本板继电器 `do1`；物体持续停留不会重复触发，离开时也不会再次翻转。DI1/DI2 双高或双低的故障组合只上报 `break_down`，不会误触发灯控。若灯接在 DO2，应将规则动作目标改为 `do2`。

## Modbus 默认参数

六台设备共享 RS485，波特率 **9600**。五个采集任务、一个继电器控制条目和相关规则已启用。传感器仅配置采集任务，不再重复建立控制条目。任务/设备索引从 0 开始，与从站地址不同。

| 从站 | 用途 | 任务 / 设备索引 | 当前默认参数 |
| --- | --- | --- | --- |
| 1 | 漏水控制器 | 0 / — | FC04，寄存器 0，1 个 UINT16，倍率 1；漏水编码待核实 |
| 2 | TVOC | 1 / — | FC03，寄存器 0，1 个 UINT16，倍率 1，ppb |
| 3 | 甲醛 | 2 / — | FC03，寄存器 0，1 个 UINT16，倍率 0.001，ppm |
| 4 | PM2.5 / PM10 | 3 / — | FC04，寄存器 0 / 1，UINT16，倍率 1，ugm3 |
| 5 | 温湿度 IVG-TH | 4 / — | FC04，温度寄存器 0 / 湿度寄存器 1，倍率 0.1；温度为 INT16 补码 |
| 6 | Modbus 继电器 | 无 / 0 | 4 通道，通道 1 起始地址 `0x0000`，FC06 保持寄存器控制，`ncMode=true` |

PM2.5 地址 `0x0000`、PM10 地址 `0x0001` 由用户提供；IVG-TH 参数依据用户提供的协议图片，漏水 FC04 已实测读通。其他未确认的协议细节采用模板默认值。设备返回异常码或超时时，应据厂家协议修改功能码/地址；数值返回成功后仍需核对未确认的单位、倍率和有符号格式。程序不会生成随机测量值。

采集规则按设备当前配置每 30 秒执行一次：地址 2–5 合并为 `s3_modbus_environment`，通过 `{"poll":[1,2,3,4]}` 顺序读取；地址 1 单独轮询，避免其超时触发整组退避。五条 Modbus 轮询规则减为两条，当前执行规则共 8 条。不同从站仍需各自的 RTU 事务；同一从站的温湿度、PM2.5/PM10 分别合并连续寄存器读取。继电器控制规则目标为 `modbus:0`，命令中的 `d=0` 指设备索引，实际从站地址为 6。

## MQTT 与灯控

本板输出初始化值为 0，保留 `s3_platform_do1`、`s3_platform_do2` 平台控制规则，并启用 `s3_photoelectric_relay_toggle`：灯接 DO1 时，有物体经过触发一次翻转，继电器当前为开则关、为关则开。Modbus 继电器通道 1 使用 FC06 写保持寄存器 `0x0000`；`ncMode=true` 表示平台“开”对应继电器线圈释放、NC 端导通，平台“关”对应线圈吸合、NC 端断开。若灯接 DO2，需要把联动规则目标改为 `do2`。

MQTT 接入信息由用户后续填写并启用。模板预置 `/property/post`（属性）、`/event/post`（设备事件，`topicType=4`）和 `/function/get`（控制）主题，`autoPrefix=true`，按设备身份生成主题前缀。平台物模型需包含 `break_down` 事件。MQTT 未配置期间不能宣称平台已经收到故障事件。

AI 转换和质量字段见[工业接口字段参考](../industrial-io-guide.md)。常规配置命令和凭据规则见[配置样例索引](../README.md#单设备部署)。

## 2026-09-22 现场问题修复（r3 当前版本）

- 温湿度按 IVG-TH 文档改为 FC04，从 `0x0000` 连读两个寄存器，温度在前、湿度在后，倍率均为 0.1；温度采用有符号 16 位补码。实际读回 `05 04 04 00 EA 02 6B DF 3F`，对应 23.4°C、61.9%RH。温度属性 ID 调整为 `modbus_temp`，避免超过固件 15 字符上限而被截断，平台物模型应使用此 ID。
- 漏水读取改为 FC04、寄存器 0、数量 1；正确单寄存器请求为 `01 04 00 00 00 01 31 CA`。用户提供的响应 `01 04 02 00 00 B9 30` 表示原始值 0，漏水/无漏水编码仍以厂家定义为准。用户重新连接漏水支路后，通过 ESP32 连续两次读回该响应，通信恢复。
- 串口证实 `pexec_w1` 栈溢出：超时告警同步触发日志文件轮转及 LittleFS 删除，耗尽工作线程栈。日志生产入口已改为只入缓冲，由既有主循环定时写盘；同时去除其余 Modbus 配置大对象拷贝。没有通过增加工作线程栈掩盖该路径。
- UART 终端用于通用串口读写，I2C 探测用于地址扫描和传感器诊断，继续保留。已补齐单条外设与列表能力字段；禁用外设或由 Modbus 占用的串口仅显示原因并禁止读写，不再显示内部 descriptor 错误。RS485 调试应使用 Modbus 协议页。
- 外设/外设执行列表删除末页最后一项后自动回到有效页；服务器和浏览器同步页码，过滤先于分页。Modbus 删除保存到设备，失败恢复列表；空配置不再从浏览器历史缓存复活。仍被执行规则引用的子设备需先处理引用，避免索引移位后控制错误设备。
- 补测发现登录后直接进入 Modbus 页面会依赖尚未加载的翻译函数，出现 `t is not defined`；两个协议模块已改为自带局部回退，新增直接入口回归通过。网页资源以 r3b 单独更新，固件保持 r3。

修复版已部署到 COM15，固件与 LittleFS 写入校验通过；构建报告 `sourceStable=true`，使用独立冻结目录避免其他任务修改源码。保留原网络、身份、认证及 MQTT 配置，仅覆盖三份现场配置和 Web 资源。

本地 711 项单元测试首轮有环境依赖缺失及一次 PowerShell 超时；补齐依赖后定向复跑原测试，合并证据为 710 项通过、1 项因 Windows 符号链接权限跳过，没有宣称整套重跑全部通过。新增浏览器回归 17 项通过，覆盖诊断入口、末页删除回退、Modbus 直接入口、删除保存/失败回滚/刷新及空列表。

实机浏览器完成两轮菜单导航：外设 9 项、执行规则 7 项、Modbus 6 项（5 采集、1 控制）；RS485 协议占用及 I2C 禁用提示正确，越界分页返回有效末页。HTTP 错误、401 和 JavaScript 错误均为 0。现场浏览器验收为只读，删除及保存失败场景由本地模拟 API 回归覆盖，未将其表述为实机删除落盘验收。

实机连续观察约 12 分钟（120 次 API 采样并同步串口采集），检查全部通过：运行时间连续、会话未失效、内存保护状态始终 `NORMAL`、串口未见崩溃，最终五个 Modbus 任务均有实际缓存且 `lastError=0`。已自然覆盖漏水读取超时后重试成功、日志文件轮转及旧备份删除，未复现旧栈溢出；观测到的工作线程最低剩余栈为 1164 字节。短期实测不能替代长期稳定性验收。
