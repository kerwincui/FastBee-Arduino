# G04/type60：动作21事件上报单次化

状态：IMPLEMENTED_ARTIFACT_NOT_RUN。本包只准备源代码、回归和文档，父任务统一串行验证后另记结果；未访问设备或 MQTT 网络。

## 已确认问题与修改

动作21先调用 triggerEventById 派生本地规则，再按 reportAfterExec 且未 suppressReport 显式通知 MQTT。原 Scheduler 的静态事件、DEVICE_EVENT 和未知 ID 路径会隐式通知一次，因此勾选上报会通知两次，关闭上报或外部抑制仍通知一次；静态/外设名称与规则名称还可能不同。

Scheduler 的事件入口和 Manager 按 ID 入口增加可选 publishToMqtt 参数，默认 true 保持普通系统事件的现有行为。动作21显式传 false 仅执行原本的本地事件路由，然后保留原条件发布一次。exec_ 与 mc: 路径原来没有隐式发布，行为不变；未知 ID 仍无本地匹配。没有添加新的队列、字符串副本、重试或常驻状态。

来源凭据继续随分发和显式通知传递；通知前仍重新检查 UART 来源是否退休，所以子规则在回调前使来源失效后不再发布。设备断线交付、MQTT重传或外部反馈循环不是本包的单次通知证明。

## 准备的回归

test_action21_single_publish.py 提取实际 Executor 动作21分支、Manager封装/通知和Scheduler三个路由函数，链接实际静态事件目录，以外围查找、子规则派发和 MQTT回调作为离线边界。冻结原动作21分支保留两次/被抑制仍发布的负例；测试404组路由、report/suppress、来源、回调与默认兼容组合，以及恢复隐式发布、忽略抑制、忽略来源退休、放行旧动态目标四个变异。当前均 NOT_RUN。

覆盖静态、DEVICE_EVENT、未知、非事件外设、exec_、mc:；显式目标和旧目标回退；无来源、失效/畸形来源、子规则退休；普通调用默认发布与显式关闭；无Scheduler/未初始化/无Manager仍沿用原动作分支的显式通知语义（真实调度准入另有守卫）；无回调与回调拒绝不会伪造送达。另增旧动态目标在启用/禁用手动执行均拒绝、显式目标接收动态负载仍通过的覆盖，移除运行时动态目标拒绝为第四变异。action_result 的 event_triggered 保持现有语义，不能代表 MQTT送达。

原 UART事件、RTC示例及动作21防环夹具附最小签名适配。整包构建容量、设备行为、长稳以及MQTT/外部反馈边界仍待单独验收。
