# 普通输出控制权与停止确认

更新：2026-10-04。本文描述已配置输出的来源仲裁，以原生数字输出为基础，逐后端接入。正式验收以统一门禁证据为准。当前没有设备部署或物理输出验收。

## 控制来源与占用

规则和 MQTT 自动控制优先级相同；HTTP 手动操作和已保存屏幕卡片优先级相同，并高于自动控制。不同来源不会隐式抢占。专用 ControlOutput 的 RESET/OE 独占关系始终优先，普通操作不能覆盖。

手动操作默认持有 30 秒，最长 300 秒。已有自动 producer 时，HTTP 单目标操作只有在用户确认覆盖、目标 ID、配置版本和占用 generation 仍一致时才可接管。同优先级的另一用户或屏幕卡片不能接管。执行规则的“运行一次”可能触达多个目标，因此不接受单目标覆盖确认。

同一次规则调用持有相同 operation，支持 HIGH→等待→LOW，以及 BLINK→STOP。规则返回前不会释放给其他 actor；规则正常结束后仍运行的 blink 继续保留 owner。自动静态写在终态释放占用。已经结束的 operation 和过期前排队的旧命令不能自动重放。

手动期限从首次获准时计算，等待期间也计时。超期后拒绝后续写入，并停止 producer；正在执行的调用保留退休中的 owner，直至收到终态确认。停止和到期不推断安全 HIGH/LOW，不自动恢复之前的自动输出。

## 失败与配置变化

blink 使用受检的定时器创建、启动、停止和删除。停止或删除失败时保留句柄、节点、owner 和错误，不能把清空本地指针当成释放成功。自动清理最多每秒重试一次，累计失败次数饱和、不回绕。旧回调只携带不复用的数字 token，不能访问已经释放的上下文。

配置、规则版本、UART 来源或已保存屏幕布局变化后，旧上下文不能继续写入。原生数字输出的旧 writePin/toggle/startActionTicker 入口不能绕过可信 context 和 permit。修改正在占用的目标配置需先结束该目标的控制；配置重载和事务快照不会清空或恢复活跃的旧 grant。

规则结果保留首个原生输出拒绝原因；后续成功动作不能覆盖该失败。accepted 仅表示本次软件/SDK 调用被接受，不表示负载、接线、电平实测或设备实物通过。

## 已扩展的后端

PCF/MCP 数字输出和 IoBlink 已接入同一来源策略。延迟节点保留原 context/permit/provider/channel；provider 被替换或停止时撤销旧授权，旧节点不能补写。待同步通道与历史写失败继续保留，软件停止不推断远端输出电平。

NeoPixel 真实 CALL 路径已接入每帧许可检查；无来源拒绝，亮度仅更新运行配置，普通 stop 撤销后续帧但不发黑帧或释放对象。11 个真实 PM/帧消费者场景已包含在上述定向验证。生命周期清理仍另行确认黑帧和资源释放，不能用普通停止代表灯带已熄灭。

PCA9685 整设备仲裁已接入候选，PWM/DAC/breathe、servo/stepper及完整 Modbus/Motor 等后端仍在集成或待测；不能把本项当作计划 9.3 或 H1 整包完成。RF 等无稳定确认协议的输出也不能推断为全来源已覆盖。实物矩阵、完整能力/运行资源/内存测量、RTC/SD/UART/NC/RGB及 24h/7d/V14 长稳仍各自开放。
