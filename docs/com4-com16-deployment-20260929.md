1. **空协议修复通过。** 依据 docs 配置结构补齐原本为空的 config/protocol.json，显式维持 MQTT=false、Modbus RTU=false。修复器拒绝覆盖非空配置；离线重挂载确认其余文件逐字节不变，设备固件匹配后仅写文件系统并独立校验。修复后记录中空协议错误为 0。证据：COM4/protocol-repair.json。
2. **最终 5 分钟 API 测试通过。** COM4/api-final-v2.json 记录 11 个样本、27 次请求、0 失败，P95 为 1,375 ms，持续时长及覆盖检查通过。身份、登录、Web 入口、3 个外设和 3 条规则回读匹配。早期连接失败仍保留，不由最后一次通过覆盖。
3. **DHT11 业务未通过。** GPIO10 的传感器读取仍失败，温湿度规则报告 FAILED 并退避。两段修复后串口记录合计 5 次驱动读取失败。需要实物核对接线、型号及供电；软件时序因素也未排除，不能只归因硬件。
4. **显示维护超预算待复核。** LCD maintenance 约 350 ms，超过 250 ms 预算；启动前 30 秒记录 9 次，约 5 分钟处再记录 1 次恢复维护超时。未证明发生崩溃，但交互延迟和周期性影响仍待验证。
5. **短窗未见严重重启异常。** 启动观察 uptime 30–90 秒；最终观察 240–360 秒。最终窗口 DRAM8 最低空闲 39,404 B、最大连续块最低 24,564 B，RSSI -76 至 -74 dBm。没有记录到 panic、堆损坏、看门狗触发、欠压或意外 uptime 回退；这不是长时间无泄漏证明。
