# 触控屏设备与 Web 配置优化改进计划

版本：v1.0（审核稿）  
日期：2026-09-22  
状态：已获授权实施。下文保留审核时的计划依据；当前实现与验证结果见[实施记录](touch-screen-optimization-implementation.md)。

本计划覆盖左侧菜单、通信协议中的远程资源、设备屏幕 Web 页面、心知天气、实体触控屏的趋势/电机/系统页面，以及设备大屏电机重复执行问题。以当前工作区代码为依据，沿用现有屏幕驱动、绘制机制、采集缓存、执行能力和 Web 样式。

建议的最终使用方式是：**在“设备屏幕 → 配置”集中选择显示内容和设置，进入“预览”查看效果；实体屏幕默认提供首页、温湿度趋势、电机控制、系统设置四类页面，按实际配置启用。** 普通用户无需填写天气 URL、字段路径、Topic、寄存器或组件坐标。

### 2.2 电机重复执行：已复现缺陷与待核查链路

已确认的缺陷位于 `device-control/core.js`：

1. `setupDeviceControlEvents()` 向 `#dc-content` 注册匿名 `click` 监听器。
2. `destroyDeviceControlPage()` 清空内容并设置 `_eventsBound = false`，但没有移除这个容器自身的监听器。
3. 同一容器重新绑定时旧监听器仍然存在，一次点击可以多次进入 `_dcMotorAction()`。

本次使用 Node 的 `EventTarget` 加载当前生产模块，运行其实际 setup/destroy 方法，替换网络与设备控制为计数器，获得以下结果：

| 场景 | 一次 click 进入电机控制函数的次数 |
| --- | ---: |
| 首次绑定 | 1 |
| 同一容器销毁/再绑定一次 | 2 |
| 同一容器销毁/再绑定两次 | 3 |

这是**本地生命周期复现**，没有向电机发送指令。它证明了足以造成重复下发的代码缺陷；现场这一次故障是否同时涉及缓存 DOM、重试或规则，需要后续结合实际请求与总线记录闭环。

另外三项一并检查：

- `_dcMotorAction()` 当前没有电机专用的在途提交约束；UI 成功响应后还会直接把状态显示为“正转中/反转中”，实际状态和命令结果需要分开。
- `handleModbusMotorControl()` 写入后调用 `triggerEventById("mc:…")`；若事件规则再次控制同一电机，可能形成第二次动作。速度/脉冲设置目前还会落入默认 `stop` 事件文案，需要修正事件语义。
- `writeRegisterOnce()` 默认继承主站重试次数；下位机已执行而响应丢失时，重发启动寄存器可能再次运行。一次 HTTP 请求不等于一次总线启动写入。

**修复次序：先消除重复监听，再补提交保护、命令语义和重试边界，最后让触屏复用同一条修复后的执行链。**

## 3. 菜单与页面信息结构

### 3.1 左侧菜单

```text
外设执行
通信协议
设备屏幕
设备大屏
……其余菜单沿用现有顺序
```

“设备屏幕”与“通信协议”为同级菜单。通信协议内部只展示编译并启用的 MQTT、Modbus RTU Tab；若某协议不可用，默认选中另一个有效 Tab，不能继续回退到已删除的 `remote-resources`。

屏幕已启用但初始化失败、暂缺显示设备时，保留设置入口并显示具体状态。未编译屏幕能力的目标不加载屏幕/天气编辑资源；直接访问旧地址应得到清晰回退。原天气入口可一次性跳转到“设备屏幕 → 配置 → 心知天气”。

### 3.2 两个 Tab，各自承担清楚的职责

| Tab | 默认呈现 | 操作 |

| 预览 | 一行屏幕状态、页面切换、居中的屏幕效果 | 切页、查看数据、定位到对应页面设置 |
| 配置 | 页面与内容、心知天气、显示与息屏三组主要配置 | 选择已有数据/电机、调整设置、保存并应用 |

运行状态收敛为一行，例如“屏幕运行中 · 480 × 480 · 配置已应用”。诊断字段、内部引用和版本号放入按需展开的诊断信息。

## 4. 心知天气精简整合

### 4.1 保留的表单

| 设置 | 是否必需 | 默认/行为 |
| --- | --- | --- |
| 启用天气 | 是 | 新配置默认关闭；已有有效心知来源继承原启用状态 |
| API Key | 启用时必需 | 仅首次或修改时输入；已设置显示掩码；留空保留；明确操作才清除 |
| 城市/位置 | 启用时必需 | 自动带入旧来源；支持服务商接受的城市名称/拼音/城市 ID/位置格式，提供一个简短示例 |
| 自动更新 | 有默认值 | 默认 30 分钟；提供 15、30、60 分钟选项，放在次要位置 |
| 更新天气 | 操作 | 保存新凭据后从设备后台读取，复用缓存和限频；有结果后显示城市、天气、气温和更新时间 |

取消提供方选择、来源 ID/显示名称、来源增删列表、自定义 URL、查询密钥参数名、Authorization、预报启用及地址、预报周期、JSON 字段映射、天气代码映射和手填过期秒数。默认只配置一个本地天气来源。

### 4.2 固定行为

- 使用心知天气实况接口 `/v3/weather/now.json`，固定简体中文和摄氏度；地址与响应字段适配内置。
- API Key 仍是调用心知天气所需的必要凭据。“删除鉴权配置”落实为删除通用鉴权选项，不会做成无需 Key 的无效配置。
- 天气显示城市、图标/天气文字、气温、更新时间，附简短的“心知天气”来源文字。
- 免费实况文档只保证天气文字、代码和气温等基础实况字段；室内湿度来自选定传感器，不能把天气服务缺失的湿度显示为 0 或拿室内湿度冒充室外湿度。
- 不显示未来预报、空气质量、体感温度等额外卡位，也不发起对应请求。
- 普通浏览、切页、图表刷新只读设备缓存。手动“更新天气”沿用至少 5 分钟的请求间隔控制；限频时显示可重试时间，不反复提交。
- 自动过期判定由刷新周期推导，建议 `max(2 × 刷新周期, 60分钟)`；这是天气数据规则，不修改本地传感器的鲜度阈值。
- 断网时保留最后一次天气并标“更新于… / 暂未更新”；错误 Key、额度限制、城市无效、时间未同步等给出可理解的状态。
- Key 不进入布局导出、浏览器本地草稿、日志、错误 URL或天气状态接口。使用现有密钥脱敏机制。

官方依据：[天气实况](https://docs.seniverse.com/api/weather/now.html)、[API 密钥](https://docs.seniverse.com/api/start/key.html)、[服务说明](https://docs.seniverse.com/api/start/start.html)、[位置等通用参数](https://docs.seniverse.com/api/start/common.html)。实施时以账户实际权限及接口响应验证，不推断所有套餐都有相同字段。

### 4.3 后台实现与资源约束

复用当前天气 worker、缓存、网络状态判断、失败退避、OTA 暂停及配置代次校验。用户表单精简，后台的有界超时、响应体限制和内存准入继续有效。

固定使用经过证书校验的 HTTPS。当前实现对 HTTPS 请求有内部内存门槛，且 4G 路径明确不支持该天气传输；因此需将“时间未同步 / 内存暂不足 / 当前网络不支持”纳入状态和验收，不能仅删掉设置就宣称所有网络可用。目标设备是否需要优化 TLS 缓冲/调度由测量决定，不通过关闭证书校验或暗中降为 HTTP 解决。

天气配置入口归属设备屏幕，规范化天气数据继续可供已有数据展示与规则读取。保持一份数据缓存和一个请求调度来源，避免屏幕、大屏、外设执行分别拉取天气。

## 5. 实体触控屏页面设计

### 5.1 默认页面与视觉规范

建议提供四类默认页面，按实际来源生成：

| 页面 | 主要内容 | 缺少配置时 |
| --- | --- | --- |
| 首页 | 时间/日期、室内温湿度、可选天气 | 隐去未启用的天气区域；已有传感器离线则保留“暂无数据/离线”状态 |
| 温湿度趋势 | 两张上下排列的时间趋势图、选中点详情 | 未选择来源时不自动生成占位图；采集暂空显示等待采样 |
| 电机控制 | 状态、速度/脉冲设置、正转/停止/反转 | 未绑定电机时不出现在默认导航；Web 提供绑定入口 |
| 系统设置 | 亮度、自动息屏、立即息屏，按需提示音/重启 | 按真实硬件能力显示相应操作 |

默认取消“场景与开关”空页、开关待配置、场景待配置和多个固定亮度按钮。已经绑定且由用户创建的有效开关/场景可以继续使用，删除目标是默认占位内容及退役远程来源。

480 × 480 参考规范：页面边距约 16 px，卡片间距 12–16 px；操作目标至少约 44 × 44 px，电机及息屏主按钮高度建议 48 px；标题、正文、关键数值建立三档字号。实际字体按现有字体覆盖和栅格效果验收，避免新增整套大字库造成体积暴涨。

全局使用统一间距、圆角、主题和状态色；重要状态带文字，不只靠颜色。内容名称尽量不超过两行。字体、单位、负数、小数、中文和窄卡片都进行实际渲染检查。

多页统一使用底部简短页名/当前位置和左右滑动；页面边缘或空白区域负责翻页。单页时隐藏多余翻页控件。滑块、输入和图表交互有自己的触摸区域，不抢占成翻页。

```text
│ 周二                  网络正常 │
│                                │

│ 20.0 °C            56 %        │
│                                │
│ 北京   晴   24 °C              │

```

时间复用系统校时；未校时显示清楚状态。天气和本地传感器分区、标明含义，不把不同采集时刻的数值拼成“同时更新”。关闭天气后回收区域给主要数据。

### 5.3 温湿度趋势

```text
温湿度趋势                        最近10次采样

温度                                  20.0 °C
22 ┤        ╭──╮
20 ┤───╮───╯  ╰──●
18 ┤   ╰──╯
   └───────────────────────────────
     16:38        16:39        16:40
                   16:40:08 · 20.0 °C

湿度                                    56 %
100┤
 50┤─────╮──────●──
  0┤
   └───────────────────────────────
     16:38        16:39        16:40
```

具体规则：

1. 横轴依据实际采样时间定位，显示起点/中点/终点等少量刻度；纵轴显示约 3 个刻度和单位。不得按等间距点位伪装成均匀采样时间。
2. 默认选中最新点，固定详情行显示“16:40:08 · 20.0 °C”；点选其他位置选最近采样点，并出现标记/细参考线。避免每个点同时叠加文字。
3. 温度自动取合适范围并留边距；湿度默认 0–100%。Web 的“更多设置”可以调整已有图表范围和精度。
4. 采样窗口不足一分钟时刻度可显示秒；跨日时带日期；没有有效绝对时间时显示相对时间/采样序号，不显示伪造的 1970 时间。
5. 继续使用最近 10 个真实采样点，不擅自扩大存储量，不把“10 点”称为“10 分钟”。后续长时间趋势属于独立需求。
6. 缺失、无效、断采或跨启动时间不可靠的区间不补 0、不编造点；必要时断开曲线并标明中断。
7. 重启恢复点标为历史；最新样本质量仍按原采集规则判断。陈旧历史不能覆盖传感器当前离线状态。
8. 选中点用稳定的 sequence/时间身份保持；新点到来时不跳成另一个旧点，点被移出窗口后回到最新点。
9. Web 预览与实体采用相同的刻度、单位、取点和质量规则。图表选点只读取快照，不触发传感器采集。

## 6. 电机控制与重复执行修复

### 6.1 触屏完整电机组件

```text
电机控制                      已停止 / 状态待确认

设定速度      50 [按设备定义的单位]
[-]           [ 50 ]          [+]   [设置]

单次脉冲      1600
[-]          [ 1600 ]         [+]   [设置]

               最近操作：参数已设置

[ 正转 ]          [ 停止 ]          [ 反转 ]

首页             趋势          电机          系统
```

设置速度/脉冲不启动电机；正转/反转使用已成功设置的参数。输入有修改但未设置时明确标注，并阻止以不明确的参数启动。用户点数值可用大尺寸数字输入面板，步进按钮只改输入；只有“设置”提交参数。

组件从 Web 一次选择已有电机，自动获得名称、允许动作、参数范围/单位和可用回读项。设置项包括显示/隐藏、默认输入值、调节步长、允许在屏幕控制；范围不得超过设备驱动允许值。默认输入值只是输入预填值，保存屏幕配置不能自动写入电机参数或启动。

首批支持当前已经注册且具备控制协议的 Modbus 电机。其他驱动只有明确实现等价能力后才进入候选，避免选择普通继电器或未知外设得到假电机界面。

### 6.2 状态必须反映实际能力

- 运行方向、停止、故障优先来自设备回读；超时显示“状态待确认/离线”，同时保留最近指令结果。
- 当前 `readStatus` 主要返回速度和脉冲寄存器，不能据此认定所有电机都有运行方向、转速或运行计数反馈。
- 没有独立运行反馈时显示“正转指令已发送 · 运行状态未确认”，不把 HTTP 成功当作电机已经运行。
- 寄存器中的设定值显示“设定速度/单次脉冲”；只有协议明确定义了实际转速和累计计数才显示相应数值。单位由设备能力给出，不无条件固定 `rpm`。
- 同步修正 Web 大屏目前收到成功响应就立即显示“正转中”的逻辑，确保两端含义一致。

### 6.3 共用执行服务

Web 大屏和实体屏幕共同调用受限的电机控制服务：

```text
Web 大屏 ─┐
          ├─ 电机命令服务 ─ 串行调度/校验 ─ Modbus 驱动 ─ 电机
实体屏幕 ─┘        │
                   └─ 操作结果/状态缓存 ─ 两端展示
```

服务接受稳定的已配置电机引用和有限动作：设置速度、设置脉冲、正转、反转、停止、读状态。协议映射来自受信任的现有设备配置，屏幕布局不携带任意寄存器或 RAW 报文。

触屏回调只排队，不在 UI 任务里同步等待 Modbus。沿用现有调度、总线互斥和软限位实现；抽取共同逻辑，避免屏幕、大屏、外设执行各自复制一套。设备目录顺序改变时不得误控另一电机，旧索引引用需校验身份指纹或映射到稳定 ID。

### 6.4 重复执行修复内容

| 层级 | 具体改动 | 必须验证的行为 |
| --- | --- | --- |
| 事件生命周期 | 将大屏容器监听改为可卸载的命名处理器/AbortController，按 DOM 实例记录绑定；销毁时卸载，重建时只绑定一次 | 首次、刷新、反复进出、全屏、页面缓存恢复后，一次点击只进入一个命令提交 |
| 前端提交 | 对同一电机的在途启动命令设置提交锁；忙碌时显示正在发送，避免 click/touch/键盘组合重复提交 | 双击和快速连点不堆积启动动作；完成后的下一次有意操作可正常执行 |
| 命令身份 | 为每次操作生成唯一请求 ID；服务按设备和 ID 记录有界的短期结果，重复到达返回原结果 | 同一请求重放不再次写；不同有意操作不被永久屏蔽 |
| 规则事件 | 区分请求、结果通知和真实状态事件；携带来源/关联 ID，阻止结果通知再次启动同一来源动作 | 关联其他设备的合法规则仍可用；同一电机自回流不产生第二次启动 |
| 协议重试 | 启动/定量运动命令在没有下位机幂等保障时不自动重发；响应丢失转为“结果待确认”，优先读回状态 | 响应丢失时不暗中补发第二次启动 |
| 停止 | 停止作为独立高优先级操作，不能被普通启动提交锁禁用；清除同电机尚未执行的启动请求 | 停止后不因排队旧启动再次运行 |

去重不能只使用“短时间相同参数全部丢弃”，否则会误拦用户连续有意执行。请求 ID 的缓存必须有容量、过期和重启边界；系统不承诺跨断电和未知下位机协议的绝对 exactly-once，无法确认结果时明确提示并禁止自动重放。

总线验收按“**启动寄存器实际写入次数**”计数：一次操作可能合理包含写脉冲、写速度、读状态等多帧，不能把任意两帧直接当作运行两次。

停止优先级受到正在进行的单次总线事务限制，需测量最坏等待时间。界面的停止不标注为硬件急停。

### 7.2 交互与同步规则

| 项目 | 实体触屏 | Web 配置 |
| --- | --- | --- |
| 亮度 | 拖动滑块即时调节，显示百分比 | 同样的滑块编辑默认值，保存并应用后生效 |
| 自动息屏 | 大尺寸列表选择：不息屏、30秒、1/2/5/10分钟 | 同样选项；已有合理自定义值可保留在更多设置 |
| 立即息屏 | 明确的单按钮 | 配置区可提供同名显式操作，显示当前睡眠状态 |
| 触摸唤醒 | 第一次触摸只唤醒，完整抬手后才允许后续操作 | 展示该固定行为，无需新增复杂选项 |
| 提示音 | 仅实际支持时显示，默认页面可隐藏 | 可决定是否显示、是否启用触摸反馈 |
| 重启 | 配置允许后显示，保留确认 | 默认折叠，沿用现有许可和重启机制 |

亮度范围正常使用 1–100%；0% 统一通过息屏行为进入，避免滑到全黑后不知如何恢复。不同后端目前存在 PWM/CH32 连续调光和仅开关两类，应增加明确的调光能力/步长；只有开关能力的后端不展示假连续滑块。

手势和持久化要求：

1. 按下先命中控件，滑块捕获当前手势，横向拖动不翻页。图表选点和页面翻页采用同样的归属规则。
2. 拖动时合并中间值，建议硬件亮度更新不超过约 10 次/秒，松手提交最终值；正常翻页/触摸目标响应先以 100–150 ms 为设计目标，实机再测。
3. 连续调整只保存最后值；停止调整约 2 秒后通过非 UI 阻塞的保存任务合并落盘，不在每次移动时写 Flash。
4. 息屏后保留已应用亮度，触摸恢复到该值。拖动和按键更新最后交互时间，不能在正在调节时自动息屏。
5. 触屏修改后的持久化值成为 Web 下次读取的当前设置；Web 有未保存草稿时显示更新提示，不自动覆盖草稿。
6. Web 保存成功后立即应用对应设置；普通页面刷新只读状态，不重复下发亮度或触发落盘。
7. 无可用触摸唤醒能力时不启用会让设备永久黑屏的自动/手动息屏；显示具体原因并保留配置入口。
8. 整个唤醒手势都被消费；在电机正转按钮位置唤醒、长按唤醒、拖动唤醒都不得穿透执行。

系统功能拥有独立的 `slider`、`button`、时间选择表现，名称分别为“亮度”“立即息屏”“重启设备”等。外设执行中的一次性动作仍保留原有含义，并允许用户按需添加快捷项；默认不单独生成“执行一次”页面。

## 8. Web 可配置能力对照与保存体验

| 实体功能 | Web 可调整内容 | 自动处理内容 |
| --- | --- | --- |
| 首页 | 启用、名称、温湿度来源、天气显示、默认首页 | 布局、名称、单位默认值 |
| 趋势 | 来源、显示/隐藏、范围/精度、页面顺序 | 对应来源历史记录、时间刻度、最新点选中 |
| 天气 | 启用、Key、城市、更新周期 | 接口、字段、图标、单位、过期/重试逻辑 |
| 电机 | 电机选择、页面显示、控制许可、预填参数、步长 | 设备映射、可用状态、范围约束、公共执行链 |
| 亮度/息屏 | 亮度、超时、系统页显示 | 触摸唤醒、拖动合并、保存节流 |
| 其他系统操作 | 提示音/重启的显示与许可 | 能力检查、必要确认 |
| 页面布局 | 添加、删除、命名、排序；更多中调整卡片 | 默认模板、响应式表单、画布边界检查 |

统一使用一个“保存并应用”入口；表单修改均先进入草稿，清楚区分“未保存”“已保存，应用中”“已应用”“应用失败/需重启”。天气更新、电机控制和立即息屏是独立显式操作，不混入页面保存。

当前屏幕、天气、历史属于不同配置接口/文件。实现时采用小范围保存协调：

- 提交前统一验证所有已修改分组，只提交发生变化的部分。
- 天气/历史依赖先保存，确认引用可用后再提交布局；历史来源以增量合并保留其他功能的记录设置，不用屏幕当前选项覆盖整个共享 allowlist。
- 各配置使用版本/代次校验；并发保存冲突保留草稿，不进行静默最后写入覆盖。
- 任一阶段失败如实标明已保存和待保存的分组，并保留可重试内容；只有全部目标保存且屏幕应用确认后才显示整体成功。
- 不宣称多个 HTTP 请求天然具有事务原子性。若需要跨文件迁移，则另用暂存/提交标记和恢复流程，见下一节。
- 普通权限用户按现有能力只读；已有开发者模式写权限继续校验，不能因重排页面而绕过后端权限。

## 9. 删除范围与旧配置迁移

### 9.1 删除与保留的边界

| 项目 | 处理 |
| --- | --- |
| 通信协议的远程资源 Tab、分片、加载器和入口 | 删除，旧天气链接转入设备屏幕 |
| MQTT 远程通道表单及发布/订阅控制能力 | 从产品和执行候选中退役，处理引用后清理实现 |
| 原 MQTT 协议连接、FastBee 上报/订阅、其他 MQTT 功能 | 继续按原配置工作；这是独立于附加远程通道的能力 |
| 自定义天气、通用鉴权、字段映射、预报 | 删除配置及运行分支，旧数据只用于迁移识别/备份 |
| 心知实况 worker、规范化数据、缓存、限频 | 精简并复用 |
| 未绑定开关/场景及默认占位页 | 从模板移除；迁移时清理被识别为模板生成的空绑定项 |
| 已绑定的本地开关、场景、自定义页面 | 保留有效内容，可在更多编辑中维护 |
| 外设执行的一次性执行能力 | 保留；移除退役远程通道动作的新增入口 |
| 旧版本枚举/动作编号 | 保留编号识别并报“来源已停用”，不能复用成另一种动作导致旧规则误执行 |

### 9.2 迁移流程

1. 在实施前记录源码快照、配置版本和产物标识。当前工作区有大量既有修改，本计划不覆盖或重置这些工作。
2. 读取屏幕、协议和执行规则的相关配置，生成迁移报告：天气来源、远程通道依赖、空占位卡、系统亮度按钮、历史来源和页面链接。
3. 对单一心知来源保留 ID、Key、城市和有效周期，移除自定义项及预报配置；布局继续引用同一来源，避免不必要的重绑。
4. 存在两个启用天气来源或仅有自定义来源时，不静默选一个覆盖。迁移界面只在此异常情况下要求选择保留来源/重新填写心知参数，其余内容继续可审阅。
5. 退役 MQTT 通道先标记停用并停止专用订阅/发送；命中旧通道的规则列明受影响动作，整条规则暂停待修复，避免悄悄执行剩余动作。规则原内容保留供查看和恢复。
6. 对确认为模板空占位的卡片执行精简；不按标题文字批量删除。合并默认亮度预设为一个滑块，保留当前亮度和息屏设置。
7. 默认新模板按四类页面生成；已有自定义布局保留。用户选择采用精简布局后才替换相应旧模板内容，保留一次撤销/备份。
8. 迁移涉及多个文件时先保存备份和新文件到暂存区，通过全部校验后写提交标记并切换。启动时识别未完成迁移并恢复，不能留下半新半旧的引用。
9. 迁移函数可重复执行且不会重复生页、重复订阅、重复创建历史记录或规则。正常 GET 请求不自动写配置。
10. 旧 API 对退役能力返回明确状态；不得继续接受旧表单写入通道/预报/自定义 URL，再让已删除功能悄悄恢复。

天气数据可暂沿用现有协议配置存储中的内部结构，通过专用设置接口管理；Web 不再整体提交协议配置。内部代码名称是否改为天气专用模块由依赖收敛决定，不能通过直接删除 `RemoteResourceManager` 连带删掉仍需复用的天气、密钥处理和数据读取。

回退要同时匹配固件、Web 资源和配置版本。含密钥的备份只存于受控设备/工作目录，不放入公开样例、浏览器草稿或版本库。历史测试和部署记录保留，不改写为本轮验证通过。

新增电机/滑块模型后要同步规范化、导入导出、校验、能力响应、快照、Web 预览和实体 hit-test，不能只修改 HTML/CSS。8 页/24 卡限制下，电机一个复合组件的按钮/输入数量仍计入资源预算。

## 11. 性能和稳定性要求

### 11.1 保持轻量

- 不新增前端 UI 框架和远程图表库；天气图标、按钮和趋势使用现有轻量资源/绘制方式。
- 屏幕/天气按需加载；打开通信协议不再拉取屏幕编辑器或天气配置资源。
- 实体复用一个 UI 任务、分条绘制和现有缓存；天气网络、Modbus 请求和配置写盘都在 UI 任务外完成。
- 基础触摸轮询当前约 20 ms、状态快照约 500 ms，Web 屏幕状态轮询当前约 8 秒；以现有值为基线，按需局部刷新，不通过大幅提高全局轮询频率获得表面流畅。
- Web 离开页面/后台标签页停止相关轮询；返回页面不叠加定时器、事件监听或 SSE 订阅。
- 天气抓取与温湿度采集分开调度；图表和电机状态尽量复用已有采集/回读缓存，避免重复轮询同一设备。
- 触屏局部状态立即绘制，反馈不等待下一次 500 ms 快照；实际电机状态按新回读结果更新。

### 11.2 必须量化的比较

| 项目 | 比较方法/目标 |
| --- | --- |
| Web 体积 | 记录屏幕模块、协议模块、天气资源、首屏和总 gzip 的改造前后字节数；通过现有预算，不先提高门槛 |
| Web 加载 | 桌面/手机切页无重复请求、无已删除分片 404、无资源长度错误 |
| 实体操作 | 记录点击视觉反馈、滑块响应、唤醒耗时；100–150 ms 为本地反馈设计目标，硬件实测给出分位数 |
| 电机 | 命令入队、首帧发送、响应/回读、停止最坏等待时间分开统计，服从实际串口与设备响应能力 |
| 内存 | 比较内部空闲/最大连续块、PSRAM、UI/worker 栈最低余量；按既有内存准入标准验收 |
| Flash 写入 | 一次连续拖动只合并保存最终值；天气状态刷新不引发配置写盘 |
| 数据 | 温湿度持续产生新样本，质量与实际采样时间一致；不提高 TTL 掩盖停采 |

本计划不承诺尚未测量的 Flash/RAM 降幅。删除复杂表单、预报和通道预计可以释放部分空间，新增电机及图表交互的净变化由构建结果决定。

### 13.2 实体功能验收（后续阶段）

- 真实屏幕检查首页/趋势/电机/系统的字体、裁切、反色、旋转、点选和触摸区域，保留照片/操作记录。

- 设置速度/脉冲与设备回读符合协议；响应丢失不重复启动；停止不被队列旧启动覆盖。

- 持续浏览 Web、温湿度采集、天气更新、屏幕交互同时运行，确认无停采、无异常复位、无静态资源失败和无持续内存下降。
- 长期稳定性若进入验收，分别记录有效 24/72 小时窗口；既有失败或其他版本的短测不能替代本轮结果。

本地浏览器、Mock 总线和构建通过，只证明各自覆盖的逻辑与产物。本轮功能实施完成时如尚未安排设备验证，报告必须明确写“本地通过，实物交互/电机运动/长期稳定性待验证”。

## 14. 审核重点与建议采用的默认决策

本稿已按以下决策展开，审核可以直接针对具体项提出调整：

1. **页面结构**：保留预览/配置两个 Tab，默认常用操作收敛到配置，复杂拖拽按需展开。
2. **天气**：单一心知实况来源；保留 API Key、城市，默认 30 分钟更新；取消预报、通用鉴权、字段映射和 MQTT 远程通道。
3. **实体页面**：首页、温湿度趋势、电机控制、系统设置四类模板；缺少对应来源不生成待配置占位页，已有有效自定义页面可保留。
4. **电机**：优先修复重复执行，再接入触屏；统一命令链；状态按真实反馈能力显示。
5. **系统交互**：亮度滑块、息屏时间列表、立即息屏按钮，首次触摸仅唤醒；设置可从 Web 调整并与触屏同步。
6. **验证边界**：当前交付仅为计划和核查结论；实施、构建结果、部署及实体验收分别记录。
