# G02/G06：触屏与扩展 IO 的 I2C 传输和地址边界

日期：2026-10-02。本批在 artifacts/system-plan-screen-i2c-stage-20261002-r1 独立准备，准备区 70/70 已通过；合入和新候选状态以实施记录为准，**不属于 r10/r11**。只执行离线 C++ 测试，没有串口、刷机、现场配置、RTC 或物理输出操作。

## 已复现问题

1. GT911 忽略寄存器地址/数据的缓冲短写；读回 -1 会转成 255，缺字节时会修改调用方的一部分缓冲。异常 available() 一直为真时排空循环无界。
2. RGB 的 CH32/TCA 控制路径忽略缓冲短写，未检查真实可读字节和 read() 返回值；错误值可能进入掩码写，短写也可能推进软件影子状态。
3. PCF8574 provider 将 read() 的 -1 转为成功的 0xff，可能把传输错误呈现为新的全部高电平样本。
4. RGB 配置预检虽然保留了控制地址，但运行期只取得总线租约，没有声明该地址；直接创建后端时不能阻止已被其它合作客户占用的控制地址。

原生产方法的 45 项定向检查为 **24 FAIL / 21 PASS**，保存在 before-r1.log。RGB 地址缺口的六个配置执行失败保存在 before-address-r2.log，每项均指出冲突情况下 begin() 仍然成功；不是实物测试。之前 before-address-r1.log 的断言子进程超时/可执行文件占用也保留，之后将测试断言改为打印并退出 86，避免 Windows CRT 断言对话框，未降低断言条件。

## 修复范围

- GT911 每次写入都核对长度，只有完整寄存器地址才继续 repeated-start 读。异常排空最多 32 次且读到负值停止；完整样本在 32 字节固定局部缓冲中组装，所有字节合法且没有残留时才一次复制给调用方。零长度、空指针、超限、忙锁/失租约均拒绝。
- RGB 核对指针/数据短写、实际可用字节与 0～255 范围，不从失败读取派生掩码写，不在失败写入后推进影子状态。初始化在同一总线锁内取得租约和独占地址；每次控制事务再次核对归属，冲突清理和失地址后的退出不得写他人的背光/蜂鸣器。
- PCF8574 provider 拒绝负值、超范围及残余数据，错误不覆盖调用方值。真实 Pcf8574 状态机回归确认这类传输错误进入失败/无效质量路径，不冒充新样本。
- 原有共享锁、非阻塞 IO provider、读改写串行与延迟回收保持；没有添加后台重试、额外动态容器或修改物理安全策略。GT911 每次读取增加固定 32 字节栈暂存，不是堆内存；运行期栈水位仍待实测。

**边界**：结束一次失败的 I2C 事务不代表外设状态已回滚；缓冲/ACK 故障可能有部分字节到达器件。这里保证错误传播和不宣称成功，不能承诺物理输出已安全关闭。RGB 的地址独占只约束使用管理器的合作客户；GT911/OLED 其它生命周期接入、裸 Wire 和外部主机不因此全部受保护。没有新增芯片身份推断或改写既有寄存器协议。
