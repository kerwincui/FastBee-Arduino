## 2026-10-03 06:25：UART文本帧丢弃与配置边界（历史增量，UNTESTED）

本轮推进G04接收数据源，而非重复已实现的UART发送排队epoch检查。源码审阅发现旧checkSerialEvents在收到第161字节时，发布前160字节并清空缓存，后续尾部又可能成为另一条规则输入；这会将一个超长/损坏数据帧拆成多个看似完整的数值或命令。

新增固定160字节 `UartTextFramer` 并接入实际调度器。恰好160字节允许；第161字节或NUL使整帧无效，前缀和剩余尾部都不发规则，直到CR/LF，或成功空读且距最后字节至少500ms才恢复。持续超长输入只在进入丢弃状态时记录原因，不按每个字节重复日志。CRLF不会制造空值，跨64字节读取拼接正常；500ms使用无符号差处理回绕和时间0。空闲边界不是协议校验，通用文本入口不支持二进制协议；手动二进制读取接口不受此分帧器处理。

读取失败后丢弃当前部分帧并排空到边界，不能把读失败之后的尾部接回旧前缀。部分帧绑定获取快照时的全局配置epoch，后续读取发现变化时同样丢弃；无关外设配置变化也可能保守丢弃一帧。快照类型/启用校验和readData在同一PM锁下，锁忙不读。仅复制UART ID后才读取/回调，不在forEachPeripheral活跃map迭代内运行规则，避免规则修改配置使迭代器失效；前一帧规则改变epoch后，该批剩余字节不继续发布。

发布前检查完整String复制、JSON overflow、序列化字节和目标String长度，失败不发送部分JSON。保留原有文本trim语义，调试日志仅输出长度，不记录原始帧载荷。每个在用数据源持有固定帧状态，删除/停用/改类型/不再被规则引用时清理；其实际内存成本与恢复行为仍待测量。

## 运行时所有权

- UartPortLease 为三个控制器提供固定大小、无堆分配的原子 generation 租约。禁止 UART0；generation 不回绕复用。共享注册表跨编译单元一致，不通过保存对象地址作为生命周期凭证。
- 通用 UART、Modbus、4G 均在重配串口前取得租约。Modbus 在 DE 引脚操作前取得租约，4G 在 PWR 脉冲前取得租约；冲突返回失败，不停止或接管原所有者。
- 通用 UART 分配避开已配置协议的固定端口及运行时其它服务；驱动初始化失败结束本次串口、移除映射、释放自己租约。读取查找和状态快照检查所有权；丢失映射不调用别人的 end。
- Modbus 保留已有总线事务锁。锁忙的 end 不释放租约；串口初始化失败在清理后释放；正常 end 只停止自己拥有的控制器。
- 4G 失败重试先在保有租约下清理上次客户端，避免重复分配遗留。disconnect 仅断网/关模块，不提前宣称控制器已释放，因为客户端仍持有串口引用；析构先销毁客户端，再 end 并释放租约。从未启动或被拒绝的适配器析构不发送 AT、关别人的串口或脉冲 PWR。
- 锁忙/未完成清理时销毁租约句柄不会自动把控制器标为空闲；这可能保留到重启，但不允许新所有者接管仍在使用的硬件。它是失败关闭，不是已经释放内存。
