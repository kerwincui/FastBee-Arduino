# 普中 PZ-ESP32 外设 Web 配置与执行改进计划及实施验收说明

> 审计基线：2026-09-13  
> 实施与 ESP32-C6 部署更新：2026-09-15（最终候选已烧录并完成回读、API 与真实浏览器复验）  
> 依据：普中 ESP32 MicroPython 攻略 V1.2、开发板功能介绍、PZ-ESP32 底板原理图、28 个基础实验、27 个扩展实验和 FastBee-Arduino 当前工作树  
> 证据边界：C6 是软件集成验证目标，不是普中 PZ-ESP32 底板外设硬件验收

## 1. 结论

当前系统已经完成 P0、P1、P2 软件实施。按本次产品收口，外设配置页只保留外设清单、筛选、新增、刷新、编辑、启停、删除和诊断入口；“板卡与资源”“自动化”“实验模板”不再出现在该页，也不再发布对应的专用 Web 资源。普中资料中的 55 项实验仅作为本文的覆盖审计清单，仍不能宣称均已在 PZ-ESP32 实物上完整通过。

按“Web 可配置、后端可校验并持久化、固件可初始化真实硬件、执行结果可观察”四层口径保守复核。审计初始状态为 A 22 项、B 17 项、C 10 项、D 6 项；本轮将舵机、DS1302、LCD1602、RFID 从 D 提升到“代码闭环、待实物”的 C，不因主机测试或 C6 验证直接提升到 A：

| 现状等级 | 基础实验 | 扩展实验 | 合计 | 占比 |
| --- | ---: | ---: | ---: | ---: |
| A - 专用链路完整或接近完整 | 16 | 6 | 22 | 40.0% |
| B - 可由通用 GPIO/ADC/规则组合 | 2 | 15 | 17 | 30.9% |
| C - 部分支持或代码闭环待实物 | 10 | 4 | 14 | 25.5% |
| D - 当前没有通用业务链路 | 0 | 2 | 2 | 3.6% |
| 合计 | 28 | 27 | 55 | 100% |

`55 = 28` 项基础实验 `+ 27` 项扩展实验的映射只保留在本说明中，用于判断现有外设类型、固件驱动和独立执行能力的覆盖程度，不进入设备 Web 页面，也不生成一键应用动作。其中 OLED 图形、TCP/UDP、BLE UART、BLE 舵机四项继续明确为“仅评估”。B/C 类仍可能依赖通用 GPIO/ADC/规则组合或缺少实物证据，不能据此视为硬件兼容证书。

本轮最终候选已经部署到 `COM11` 的 ESP32-C6，并在保留设备活动配置的前提下写入应用与新 Web 资源。设备回到 STA `192.168.5.22` 且 MQTT 在线，Web 冒烟 38/38、功能临时启用后的 API 冒烟 46/46、真实浏览器启停和 5 次 `deviceControl` 进出页循环均通过。该 C6 没有连接普中底板、舵机、SD、RFID、UART 回环、编码器、DS1302 或 LCD1602；BLE、TCP/UDP 和 OLED 图形继续停留在评估阶段，没有执行对应功能测试。

## 2. 验收口径

| 层级 | 通过条件 | 不能替代的证据 |
| --- | --- | --- |
| 1. Web 配置 | 类型可发现；引脚角色、默认值、范围、单位正确；不展示假能力 | 仅有静态下拉选项不算通过 |
| 2. 校验与持久化 | 前后端约束一致；新建、编辑、导入、导出和重启回读一致；失败全回滚 | HTTP 200 或内存中有对象不算持久化成功 |
| 3. 固件初始化 | 真实 `begin/init/mount` 成功；资源冲突可诊断；禁用/释放生命周期完整 | mock/native 不能证明寄存器和时序正确 |
| 4. 执行与反馈 | 可读取或控制；返回值、单位、耗时、时间和稳定错误码；有硬件在环证据 | 配置回读不能证明外设真实动作 |

只有四层都通过的类型，才可标记为“完整支持”。

## 5. 目标 Web 体验

### 5.1 信息架构

| 视图 | 内容 | 用户任务 |
| --- | --- | --- |
| 外设 | 外设清单、类型筛选、配置状态、运行状态和 CRUD/诊断入口 | 创建、测试、启停、编辑和删除外设 |

外设执行继续使用独立侧边栏页面，不在外设配置中重复入口。板卡 profile 和资源规划器只参与固件初始化及保存前预检；55 项实验映射只存在于本文，不进入产品 Web 信息架构。

### 5.2 创建向导

1. 设备先返回可用外设类型、构建功能和运行功能；板卡及资源约束由保存前预检内部使用。
2. 用户选择外设类型，而不是猜枚举值或从资料实验反推配置。
3. 表单按 `TX/RX`、`SDA/SCL`、`MISO/MOSI/SCK/CS`、`A/B` 等角色展示引脚。
4. 默认推荐安全引脚，对 Flash、输入专用、启动绑带、ADC2/Wi-Fi 和控制台引脚分级提示。
5. 保存前预检 GPIO、总线、通道、定时器、串口和内存，展示资源差异。
6. 必须先保存为禁用，不在“保存”时启动电机、舵机、继电器或激光。
7. 执行有超时和安全停止的单次测试，页面显示请求、实测值、单位、耗时、时间和稳定错误码。
8. 测试成功后再由用户明确启用；失败时保留旧配置并告知回滚结果。

### 5.3 状态与操作

“已保存”、“已初始化”和“有有效数据”必须是三个独立状态。每项外设至少展示名称、类型、引脚角色、运行状态、最近值/单位/时间、最近错误、连续错误数，以及“测试、启停、编辑、删除、查看规则”。

参数使用数值输入、滑杆、开关或选项控件，不让普通用户手写隐藏协议 JSON。手机宽度下表格转为带标签的行块，操作收口到可访问菜单，不产生水平滚动。

### 5.4 功能开关与内存策略

| 能力 | 最终策略 | 内存与运行边界 |
| --- | --- | --- |
| 外设配置、外设执行 | 系统基础能力，不放入功能开关，不允许用户停止 | 页面按需加载，但 CRUD、诊断和执行后端始终保留 |
| MQTT 协议 | 保留协议页的启停开关，出厂默认启用 | 空身份/空密钥不伪造设备凭据；停用时释放 MQTT 运行资源 |
| MQTTS | 独立开关，默认关闭 | TLS 握手在无 PSRAM 设备上需约 42 KB DRAM，仍受连续内存准入保护 |
| 设备控制面板 `deviceControl` | 独立开关，默认关闭 | 没有常驻设备 RAM；进页时仍有 Web 流式输出和聚合 API 瞬时峰值，因此关闭时不加载模块也不请求数据，开启后逐项分块输出并只复制一次传感器快照；离页立即清理 SSE、计时器、请求和缓存 |
| 多用户管理 `userAdmin` | 独立开关，默认关闭 | 菜单和后端管理接口同时门控 |
| mDNS、OTA、BLE 配网、设备日志 | 保留现有独立开关 | BLE 关闭时不创建配网对象；BLE 停止接口始终可用于释放已有资源 |
| 规则引擎与命令脚本 | 合并为一个可见开关，默认关闭 | 保留旧键迁移兼容，UI、持久化、资源估算和后端执行使用同一有效状态 |
| `ledScreen` | 删除 | 无真实产品能力，不再发布元数据、构建宏或默认配置 |
| 通用 TCP/UDP 产品配置 | 删除 | 保留 HTTP/MQTT 所需的底层网络协议栈和旧 `/config/tcp.json` 清理兼容，不暴露任意 Socket 服务 |

`deviceControl` 的结论不是“常驻占用很大”，而是“打开页面会制造短时请求与序列化峰值”。因此保留默认关闭的独立开关比删除更合适。最终 Web 版本在 C6 连续 5 次进出页前空闲堆为 138,424 bytes，结束后为 140,108 bytes；设备报告的历史最低空闲堆为 107,036 bytes，离页后计时器、延迟、请求、SSE 引用和页面缓存均已释放，未观察到持续性 RAM 损失。关闭状态下未加载控制模块，也未发起控制业务 API。

## 6. UART 与编码器本轮改进

### 6.1 UART

- 默认值和持久化字段统一为 `baudRate/dataBits/stopBits/parity`。
- 支持 5-8 数据位、N/O/E 校验和 1/2 停止位的完整帧格式映射。
- UART0 保留给日志控制台；新增、更新和启用前均检查可用端口数。
- Web 终端支持文本/HEX，严格拒绝非法 HEX 和超过 128 bytes 的负载。
- 读取结果包含文本、HEX、可用 RX、已发/已收字节数、端口、连接状态和帧格式。
- 保留 CR/LF 或空闲超时分帧数据源；文本/HEX 终端和单次测试入口已纳入外设诊断。物理回显、溢出和断线行为仍待接线验收。

### 6.2 编码器

- 默认分辨率统一为 20 脉冲/转。
- 固件只支持 GPIO ISR，因此 Web 中断开关保持选中且禁用，不再暗示有轮询模式。
- ISR 同时读取 A/B 相，记录累计计数、增量、方向和边沿周期。
- API 和 Web 诊断返回 `count/delta/direction/frequencyHz/rpm`，清零需要明确确认。
- 执行规则的目标类型由错误的保留类型 46 改为编码器类型 43；`pulse` 默认读 `count`，`frequency` 默认读 `frequency`。

### 7.3 残余告警与边界

- 本轮已通过芯片类型、版本和 BASE MAC 三项确认目标为 `COM11` 的 C6；`COM4` 及其他串口设备均未写入。
- 分区表没有 core-dump 分区，崩溃时无法保留 Flash core dump。
- C6 是无 PSRAM 软件集成目标，未连接普中板外设；不能用它替代 PZ-ESP32 的电气、引脚、时序和动作验收。
- 启动早期的“网络未连接”是异步扫描前的中间状态，最终 STA/MQTT 已正常连接。
- Modbus 被当前运行功能配置禁用，因此启动时跳过是预期结果。
- 无 PSRAM C6 使用异步 SNTP 降级，不执行高内存的 HTTP NTP 路径。
- C6 构建明确关闭 BLE；BLE、TCP/UDP 和 OLED 图形没有进入功能执行测试。
- LittleFS 是可变文件系统，登录和配置规范化会改变整镜像摘要；本轮独立的启动后整分区验证因此报告摘要不同，但写入时校验和最终 `/www` 52/52 文件哈希、`/config` 语义检查均通过。
- 本轮没有舵机、UART TX/RX、编码器、SD、RFID、DS1302 或 LCD1602 接线，不宣称相应物理动作已通过。

## 8. 部署安全改进

历史 C6 部署发现，直接上传仓库生成的完整 LittleFS 会同时覆盖 `/config`，使设备丢失 STA/MQTT 运行配置并回到 AP 模式。本轮已按“活动配置 + 新 Web”重新生成候选镜像，解包校验后写入并再次读回；设备活动配置、STA 和 MQTT 均保持正常。

本次人工流程已经执行以下门槛，后续应固化为单一可回滚命令：

1. 烧录前导出活动配置，并记录不含密钥的文件清单和哈希。
2. 在独立 staging 目录合并“活动 `/config` + 新 `/www`”，不把设备密钥写入跟踪的 `data/config`。
3. 生成 LittleFS 后重新解包，逐文件核对配置和 Web 哈希；设备测试后再次读回，按 Web 字节哈希和配置语义分别验收。
4. 只写数据分区，并要求烧录工具即时验证。
5. 重启后同时验证 STA IP、MQTT、设备身份、外设数量和 Web manifest。
6. 任一核心检查失败，使用烧录前备份恢复，不将“页面可打开”当作部署成功。

在这条流程完全自动化前，普通 `uploadfs` 不应被视为“保留设备配置”的 Web 升级方式。整分区摘要不同也不能单独触发恢复，必须先判断差异是否只来自预期的可变配置文件。

## 9. BLE、TCP/UDP、OLED 图形评估

本节仅做评估。本轮没有实施这些能力，也没有对 BLE、用户级 TCP/UDP 或 OLED 图形执行功能测试。

| 能力 | 现状与风险 | 评估结论 | 进入实施的前置条件 |
| --- | --- | --- | --- |
| BLE UART / BLE 舵机 | C6 当前 BLE 构建能力关闭；现有 BLE 偏配网，不是通用数据通道；GATT、配对/鉴权、断连恢复和 Wi-Fi/MQTT 共存堆预算未建立 | 继续保持 P3，不用配网 BLE 伪装为实验 BLE UART | 先完成 P0/P1 普中板验收；定义独立 feature 预算、GATT 契约、鉴权策略和 Wi-Fi+MQTT+BLE 长时压测 |
| 用户级 TCP/UDP | 现有 HTTP/MQTT 内部套接字不等于用户可配置 Socket；开放任意目标会产生内网代理、内存、吞吐和审计风险 | 继续保持 P3，未执行 TCP/UDP 功能测试 | 定义 client/server 分离 profile、目标/端口白名单、连接数、包长、速率、超时、鉴权和审计限制，再做 C6 内存压测 |

如果后续只能从三者中选一个开始设计，受限 OLED 图元的安全边界最清晰；但它仍应等待显示 descriptor 和实物文本显示门槛完成。BLE 和 TCP/UDP 不进入当前 C6 发布镜像。

## 10. 后续执行顺序

P0、P1、P2 软件实施已经完成。剩余工作按风险从“板卡事实”到“有源执行”再到“长期稳定性”推进：

1. **冻结软件基线**：保留当前固件摘要、外设工作区边界契约、C6 证据和双份全 Flash 备份；后续修改先跑 Host、Native、离线浏览器和 C6 构建。
2. **PZ-ESP32 板卡门槛**：对照原理图、丝印和跳线，实测 Flash/启动风险引脚、ADC2/Wi-Fi、5V/3.3V 边界及可共享 I2C/SPI 总线。
3. **低风险输入优先**：依次验收按键、ADC、DHT11、DS18B20、超声波、红外和编码器，记录正常值、断线、反相、抖动、超时和重启回读。
4. **总线与存储**：依次验收 BMP280/MPU6050、LCD1602、RFID 和 SD；每项包含错地址/错密钥、拔插、共享总线、恢复和长时堆趋势。
5. **通信链路**：先做 UART TX/RX 回环，再做双设备分帧、HEX、溢出、乱码和断线；TCP/UDP 不随本批次执行。
6. **有源输出最后**：对 LED/蜂鸣器/继电器/电机/步进电机/舵机逐项确认默认安全态、外部供电、超时停止和页面离开清理；舵机覆盖 0/45/90/135/180 度。
7. **失败注入与体验验收**：注入 Flash 写入、初始化和回滚失败；在 390 px 与桌面重复完成预检、保存、测试、停用和删除，确认错误可定位且旧配置不丢失。
8. **P3 保持评估态**：BLE、TCP/UDP、OLED 图形不实施、不烧录、不做功能测试；只有进入条件完整且用户重新授权后才建立独立计划。
