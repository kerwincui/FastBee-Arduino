# NC01～NC04 独立用户验收操作卡

> 归属：整体改进计划 G05/G06、V14。材料已编写，实际试用全部 **NOT_RUN**。本文件不是支持清单，也不证明所列页面能力已经齐备；缺少表单、模板、诊断或迁移预览时应记录产品缺口，不能让开发者手改配置绕过。
> 候选版本、硬件、接线、试用人员和验收阈值尚未填写，不使用历史设备通过记录补齐。

## 1. 开始前必须确认

- 试用者未参与对应功能实现。实施者可提供本文与接线说明，不代操作，不提供隐藏 API、JSON、脚本或 C++ 修改作为正常步骤。
- 记录设备型号/板型修订、MAC 的脱敏标识、固件和 Web 制品哈希、配置版本与接线图。源码版本不能仅写 Git HEAD，须关联候选输入摘要。
- 先备份现场配置，保留目标设备身份、认证、网络、MQTT 与原有规则。公示材料不包含密码、令牌、私有地址或完整备份。
- 仅在既定设备授权范围内执行。未核实的继电器、电机、泵阀、功率负载不操作；NC01 首次应使用已确认的低风险测试负载。本文不增加设备或危险输出授权。
- 独立填写适用范围和期望结果。缺硬件/接线/安全条件/独立试用者记 BLOCKED；界面缺少必要能力记 FAIL（产品缺口）；不适用项说明理由，不能静默略过。
- 测试前确认旧配置可恢复，并确认恢复不会覆盖设备身份。故障注入、重启、断网各自有授权和恢复入口，不在正在进行的部署或长稳窗口中插入操作。

## 2. 统一记录规则

每项使用 PASS、FAIL、BLOCKED、NOT_RUN、N/A 之一，区分页面保存、实际生效、有效采样、命令响应、设备读回和物理反馈。只有取得对应证据才写 PASS。

| 字段 | 填写要求 |
| --- | --- |
| caseId / 操作时间 / 试用者 | 如 NC02-03；使用带时区的时间；试用者用非敏感标识 |
| 候选与配置 | 输入摘要、固件/Web 哈希、板型、配置摘要；不能拼接多个候选的通过结果 |
| 前置条件 / 输入 | 接线、负载、采样/阈值/单位、已核验模板来源；未提供就保留未填写 |
| 预期 / 实际 | 预期先填；实际记录可见值、时间、状态和错误；不根据实际结果倒填阈值 |
| 证据 | 截图、脱敏上报记录、设备状态、物理观察分别链接；每轮独立目录，不覆盖失败 |
| 帮助 / 卡点 | 提示文字、点击路径、是否需要开发者介入及介入内容 |
| 结论 / 恢复 | 状态、问题编号、恢复过程与恢复结果；恢复成功不抹去原失败 |

自动化/Mock 回归只能链接为 E2 附件。真实硬件 E4、持续运行 E5 和独立用户 V14 分列，自动化不能代签人工记录。

## 3. NC01：温控继电器

前置：已支持的温度传感器、输出模块、已核实接线和低风险负载；评审通过的单位、上下阈值、回差、最小开停时间、失鲜期限与故障安全状态。未核实这些参数不启用输出。

| 用例 | 试用者通过页面完成 | 验收点 | 初始状态 |
| --- | --- | --- | --- |
| NC01-01 | 在功能配置、外设配置中选择传感器和输出，按接线说明填写引脚/通道 | 预检说明资源冲突；读数包含正确单位与有效性；保存与生效有区别 | NOT_RUN |
| NC01-02 | 在外设执行中选择数据源、温度条件、回差、最小开停时间及故障安全策略 | 所需能力均有表单；缺任一必要字段记产品缺口，不用脚本补上 | NOT_RUN |
| NC01-03 | 按评审过的方法改变温度，观察阈值两侧及附近的运行 | 与事先填写的上下阈值/时限一致，不抖动；命令、读回和物理负载反馈分别记录 | NOT_RUN |
| NC01-04 | 在允许条件下制造传感器失鲜/断线并恢复 | 失鲜不变成有效 0；状态可理解；故障安全与恢复策略符合约定 | NOT_RUN |
| NC01-05 | 经确认重启后检查规则与输出，再用页面停用并恢复原配置 | 重启不意外驱动负载；停用结果可验证；恢复不覆盖身份/凭据 | NOT_RUN |

## 4. NC02：数据采集与 MQTT 上报

前置：已有传感器、获准的 MQTT 测试接收端、已约定采样周期/字段/单位/失鲜策略；不能向未授权平台发送现场数据。

| 用例 | 试用者通过页面完成 | 验收点 | 初始状态 |
| --- | --- | --- | --- |
| NC02-01 | 在外设配置中添加传感器并检查读数 | 采样成功、失败和未采样明确区分；字段/单位/时间可解释 | NOT_RUN |
| NC02-02 | 在通信协议中配置 MQTT，绑定采样字段和监控显示 | 不手写脚本/JSON；认证信息不进入截图；页面与接收端字段一致 | NOT_RUN |
| NC02-03 | 对比本地显示、规则取值和 MQTT 消息 | 同源数据、倍率、单位与质量语义一致；采样时间与消息到达时间分别记录 | NOT_RUN |
| NC02-04 | 经确认断开测试网络，再恢复连接 | 离线/缓存年龄可见；队列有界有依据；按约定恢复，不把旧值冒充新采样 | NOT_RUN |
| NC02-05 | 经确认重启，并从页面检查保存状态与恢复采集 | 身份/规则/绑定保留；无效样本不被作为有效 0 上报 | NOT_RUN |

## 5. NC03：只读 Modbus 仪表

前置：确切仪表型号/修订及已核验只读模板，包含串口参数、地址、功能码、寄存器、倍率、字序和单位。没有核验模板时记 BLOCKED；不得现场猜测寄存器或开放写命令。

| 用例 | 试用者通过页面完成 | 验收点 | 初始状态 |
| --- | --- | --- | --- |
| NC03-01 | 从界面选择/导入经过核验的只读模板 | 型号/版本/适用范围明确；需要手写帧或 JSON 才能继续即为产品缺口 | NOT_RUN |
| NC03-02 | 填写地址、串口和接线，绑定工程量显示 | 不改业务逻辑；冲突预检在生效前阻止错误资源组合 | NOT_RUN |
| NC03-03 | 对照仪表参考读数核实倍率、字序、单位 | 容差先约定；协议读回与校准/物理测量分别记录 | NOT_RUN |
| NC03-04 | 在授权测试链路中验证超时、短帧及 CRC 异常，再恢复 | 显示失败类型和失鲜，不复用旧值为新样本；未验证写功能始终不可自动开放 | NOT_RUN |
| NC03-05 | 经确认重启并恢复模板配置 | 绑定和逻辑 ID 保留；恢复后重新取得有效样本才显示有效 | NOT_RUN |

需要专业工具产生坏帧的步骤由测试负责人单独执行并留证；目标用户只需通过界面理解问题与恢复，不要求其编程。缺故障注入条件不伪记通过。

## 6. NC04：迁移到受支持板卡

前置：源/目标板卡在已声明支持范围，目标现有配置已备份，两者身份/凭据保全策略明确；业务输出默认停用。

| 用例 | 试用者通过页面完成 | 验收点 | 初始状态 |
| --- | --- | --- | --- |
| NC04-01 | 从源设备导出可复用的脱敏方案 | 版本/依赖/资源要求可识别；不夹带现场密码/令牌 | NOT_RUN |
| NC04-02 | 在目标设备预览导入差异并重新映射接线 | 显示不兼容驱动、缺失能力、保留引脚和总线冲突；没有预览视为产品缺口 | NOT_RUN |
| NC04-03 | 在页面修正问题并保存 | 失败不清空有效旧配置；危险输出未自动启用；目标身份和凭据未覆盖 | NOT_RUN |
| NC04-04 | 检查数据源、逻辑 ID、规则与展示绑定 | 未改变业务含义的 ID/规则尽量保留；必要变化显式展示，不产生悬空引用 | NOT_RUN |
| NC04-05 | 经确认重启和恢复原配置 | 迁移方案能恢复；身份保持；无法无损回退时明确阻止并记录 | NOT_RUN |

## 7. V14 退出条件与交接

1. 一名或以上未参与实现的目标用户独立完成适用场景；记录所有帮助与卡点，不只记录成功画面。
2. 每个必需用例均有候选绑定的实际证据；FAIL/BLOCKED/NOT_RUN 不计通过；N/A 有书面理由且不能免除已承诺支持范围。
3. 至少完成适用的重启和故障恢复，设备配置可恢复，秘密数据未泄露。
4. 将界面缺口回流 G05，动作/质量缺口回流 G04，资源/生命周期缺口回流 G01～G03；实物/长稳另交 G06。
5. 仅完成本文不表示向导、模板、四个场景或 V14 已完成。最终结论回填 [实施记录](system-improvement-execution-20261001.md)，不得以文档数替代产品验收。
