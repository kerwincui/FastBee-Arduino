## 本轮实现

- `PendingReportQueue` 替代共享无锁 vector。固定 5 个槽位，每条最多 512 字节，字符串按需分配，移除时释放；不分配整批报告副本。低于原有 10000 字节 DRAM 门槛或分配失败拒绝新报告。
- 独立互斥锁零等待准入，准备字符串在锁外；协议回调和日志也在锁外。重试时固定队首，在途期间不能淘汰或修改其字符串，递归/并发重试不能再次提交同一队首。
- 回调返回 false 保留原报告，返回 true 才移除。完成结果通过原子 release/acquire 交接，后续持锁操作只结算一次；不会因完成时锁忙而丢失接受结果或重复发送已接受条目。实际 MQTT 接受仅指本地发送队列接受，不证明平台收到。
- 连接恢复后每 5 秒最多重试 1 条，替换原一次搬走整批的实现；一次拒绝不清空后续报告。保持原容量策略：无在途回调且满额时淘汰最旧一条；在途且满额时拒绝新报告保护借用中的队首。因此失败留存不代表永久保留，后续满额仍可能淘汰并计数。
- 规则报告和数字输入变化报告在 MQTT 本地队列拒绝时也尝试离线缓存；不会误记为缓存成功。计数器饱和而非溢出回零。
- 列表 API `GET /api/periph-exec` 新增 `pendingReports`：可用性、容量/深度、在途、最旧入队年龄、累计入队、淘汰、格式/长度、内存、满额和锁忙拒绝、重试本地接受/拒绝。`contention` 计入入队和重试锁竞争；`rejectedBusy` 只计因锁忙未缓存的新报告，不能混为丢弃总数。不可用时不返回正常空队列。
- 页面沿用规则列表请求展示状态，不增加轮询。旧固件、忙锁、缺字段、非法数据和请求失败显示未确认；页面离开和请求代际检查阻止迟到成功/失败覆盖新页面。不展示缓存载荷、目标身份或凭据。
