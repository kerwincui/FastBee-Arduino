## 2. 已实现的用户功能

### 导航和屏幕配置

- “设备屏幕”位于“通信协议”下方；通信协议不再提供远程资源 Tab，也不再加载其旧分片。
- 设备屏幕保留“预览”“配置”两个 Tab。预览用于查看显示效果；页面内容、天气、亮度和息屏集中在配置中，布局编辑按需展开，沿用已有样式。
- 默认内容按首页、趋势、电机、系统四类组织，按实际来源和绑定生成；不再自动放置未配置的开关/场景卡。已绑定的本地控件和自定义布局继续保留。
- Web 预览不下发实体控制。保存仅提交发生变化的分组；天气与历史依赖先处理，布局随后提交。历史来源增量合并，保留已有共享 allowlist。
- 不把多次 HTTP 请求描述为原子事务；中途失败保留草稿并说明已保存分组。天气和布局分别校验版本，冲突返回 HTTP 409。

### 心知天气

- 单一心知天气实况来源，用户只需启用、API Key、城市和 15/30/60 分钟更新周期，默认 30 分钟。
- 固定使用心知 `weather/now.json` HTTPS 接口；移除自定义 URL、通用鉴权、字段映射、预报及附加 MQTT 通道的运行分支和配置入口。
- 密钥留空保留，显式清除才删除；启用但缺少密钥会被拒绝。读取接口提供 `hasApiKey`，不返回原始密钥；状态只复制允许展示的实况字段。
- 天气读取继续复用独立 worker、缓存、五分钟手动刷新限制及失败退避。保持证书校验、NTP、内存和 OTA 准入；蜂窝网络不支持天气 HTTP 时明确报错。免费字段没有湿度时不生成虚假数据。
- 新接口为 `GET/POST /api/screen-panel/weather` 和 `GET/POST /api/screen-panel/weather/refresh`。旧远程资源接口返回 410；普通 MQTT 协议功能继续使用自身配置。
- 相同配置重复保存不重置缓存、手动限频或在途请求；配置代次变化后，旧网络响应不能覆盖新来源。

### 电机控制

- 修复大屏容器保留但监听未卸载的问题；使用页面生命周期清理和每电机待处理状态约束，重复进入页面不会累积启动操作。
- Web 大屏、触屏和相关执行动作共用受限电机服务。命令关联请求 ID，重放返回已有操作；停止使用预留队列空间并优先处理，取消同电机尚未执行的旧启动。
- 有限运动启动写入不自动重试，避免响应丢失时重复运动；继续执行参数范围、配置绑定及软限位检查。
- 电机卡显示设定速度、单次脉冲和正转/停止/反转控件。参数草稿与反馈分开，设定参数不等同启动。
- 速度按设备精度显示，与 Web 大屏一致；命令保留原始寄存器值。按钮只接受实际矩形范围内的点击，间隙不触发。启用确认的卡片先确认再发命令，停止不受确认和未提交参数阻挡。
- “发送成功”不再伪装为真实运行方向或转速。缺少实际运动反馈时明确显示运行状态未确认；读回值仅表示相应寄存器反馈。
- `motor-result` 事件不会通过规则再次控制同一电机；其他目标和正常用户命令事件仍可触发有效规则。

### 实体趋势和系统页面

- 趋势沿用最多 10 个真实采样点，增加时间/数值刻度和点选详情；处理不均匀采样、无校时、恢复历史及过期数据，不生成伪造时间序列。
- 亮度采用滑块，自动息屏采用选择控件，立即息屏采用明确按钮。系统操作不再使用通用“执行一次”文案。
- 首次触摸只唤醒屏幕，吞掉该次触摸直到释放；滑块手势不穿透为翻页或其他控件动作。
- 亮度区分连续调节与硬件仅开关的能力。触屏设置通过后台任务在最后变更约 2 秒后合并保存，避免每个拖动事件写 Flash；保存仍校验配置版本并报告失败。
- 继续使用现有分条绘制与触摸处理，不引入新的 UI 引擎。已删除预报快照结构、每卡预报数组及其读取/复制/序列化，减少无效快照占用。
- 追加固定底部首页导航：点击返回 Web 设置中的默认首页，内容绘制和命中共同使用扣除底部 44 像素后的区域，不遮挡卡片；浏览器预览的首页按钮只切预览。
- 追加蓝灰/青蓝配色、卡片标题分区与类型图标、低饱和电机按钮、亮度填充轨道及刻度。沿用原有主题与绘制引擎，未引入图片资源。
- [首页绘制效果](../artifacts/touch-optimization-20260922/visual-review/screen-home.png)与[电机绘制效果](../artifacts/touch-optimization-20260922/visual-review/screen-motor.png)由生产 U8g2 渲染器生成，使用示例数据；并非实屏照片。9 组像素测试通过，组合场景在 5 种条带高度下逐像素一致。

### 编辑外设执行弹窗（追加需求）

- 规则名称和启用状态独立置顶；下方按“数据与记录”“屏幕操作权限”分组，桌面双列、手机单列，复用原有表单样式。
- “允许面板控制”明确为“允许设备屏幕控制”，授权屏幕调用支持的规则动作，默认关闭；后端安全校验继续生效。
- “记录最近十条”明确为“保留最近 10 条采样”，用于数值趋势，只有支持的采集/读取动作可启用；它不是执行日志。
- “管理最近记录”在新标签页定位到设备屏幕的历史配置，当前规则弹窗和未保存字段全部保留。该入口不保存、不执行规则。
- 桌面及手机截图见[桌面弹窗](../test-results/ui/periph-rule-options-1280.png)、[手机弹窗](../test-results/ui/periph-rule-options-390.png)；浏览器同时核验默认值、无溢出、新标签页和草稿保留。

## 3. 迁移、持久化和回退

迁移只在初始化或用户明确保存时写入，普通配置/状态 GET 不改文件。涉及的备份如下：

| 文件 | 用途和行为 |
| --- | --- |
| `/config/protocol.pre-screen-weather.json` | 首次天气迁移前保存旧协议配置；包含原凭据，按敏感配置保护，不公开导出到样例 |
| `/config/periph_exec.pre-screen-remote.json` | 保存含退役通道动作或来源的旧执行规则，规则原内容保留供修复 |
| `/config/screen_panel.json.touch-v1.bak` | 首次触控布局迁移的原始副本，不用后续版本覆盖 |
| 各主文件的 `.tmp` / `.bak` | 继续使用已有验证、原子替换及上一代恢复流程 |

单一有效心知来源保留原 ID、密钥、城市与可用周期，已有布局引用无需重绑。多个来源、自定义来源或无效旧凭据进入明确选择/修复流程，不能静默挑选覆盖。迁移报告只暴露来源 ID、名称、位置和兼容性等允许字段。

远程通道立即停止发送/专用订阅，旧观察值失效。动作编号 33 保留为退役编号；包含该动作或 `remote.*` 触发来源的整条规则暂停，不能重新启用，也不能通过手动执行先运行前序动作。原内容不被替换为其他类型。

屏幕迁移以模板 ID、形状和空绑定识别旧占位卡，不按标题批量删除。只合并匹配的默认亮度预设，并保留有效自定义控件、页面身份与导航。先验证并备份，再替换主配置；失败保留原配置并报告。

同时修复通用配置保存问题：关键文件写盘失败不再提前暴露候选缓存；成功后才使旧缓存失效。非关键小配置的延迟写语义不变，大文件写失败保留先前待写入的有效内容。回退需匹配固件、Web 资源和配置版本；本轮未执行设备回退，后续授权部署及备份见独立部署记录。

## 6. 最终构建矩阵

共享 `.pio`、Native、Web 发布使用仓库锁串行执行。首轮最终矩阵在 ESP32-C6 4MB 遇到固件超出 app0 40,432 字节，容量门禁正常阻止通过。分析发现 `ASYNCWEBSERVER_REGEX=0` 在依赖库的 `#ifdef` 下仍启用正则引擎；项目路由实际使用固定路径或前缀，没有正则路由及 `pathArg()` 调用。已改为显式 `-UASYNCWEBSERVER_REGEX`，恢复原配置关闭正则的意图，并加入继承配置与错误定义的回归约束。没有修改分区容量或删除用户功能；九目标已按修正后配置全部编译通过，下表以这次结果为准。

C6 4MB 修正后为 3,118,000 字节，比失败产物减少 264,768 字节，实际 app0 剩余 224,336 字节；经典 ESP32 4MB 的余量也从 384 字节增加至 266,176 字节。这里是同目标本地固件体积对照，不代表设备运行内存或性能提升。构建开关回归证据见 [regex-flag-contract.log](../artifacts/touch-optimization-20260922/regex-flag-contract.log)。
