## 范围与不变项

- 只处理COM4和COM16，目标是关闭非必要mDNS、减少内存占用并验证实际效果；不是确认网络故障根因。
- 保留Web管理、鉴权、原网络身份/凭据、MQTT状态、外设与规则；不触碰COM15、COM8或实际负载。
- 旧失败与release阈值保留；网络故障移出本轮修复范围，但零样本/缺测不能算通过。
- 旧现场网络对照请求已因用户缩小范围撤销，不再等待或重复催促。

## 执行步骤与状态

1. 核对现有mDNS配置及已部署代码，优先利用现有关闭路径，补充运行时停止/持久化/无意外业务变更的针对性测试。
2. 选择最小部署方式，若仅配置修改即可达到目的，不为关闭开关重写全部固件。
3. 每台设备依次取得共享锁、新鲜身份、完整私有备份及回退材料；维护前封存旧监测边界。
4. 验证实际关闭、配置/固件写入校验及非目标配置保持；建立独立内存/软件观察窗口。

## 回退材料与边界

每台同一bootloader会话保存full-flash-before.bin、独立MD5/SHA256、prewrite-gates.json和修改后文件系统。回退不得直接覆盖整片Flash；必须重新取共享锁和新鲜身份、保全期间新增配置，只恢复目标mDNS开关或经明确核验的原文件系统分区。未完成写入/校验时保持失败证据并停在恢复审查状态，不用反复复位/重刷掩盖。

私有Flash、配置和原始串口日志保存在被Git忽略的本地产物目录；公开文档不包含凭据。仓库部署技能仍是占位模板，本轮使用现有共享锁、私有备份与分区验证机制。scripts/disable-device-mdns.py的设备操作依赖本机已有的保全工具和r6/r5构建/部署档案；单元测试不依赖私有备份。
