# G02：W5500 与共享 SPI 的可确认生命周期

日期：2026-10-01。属于整体计划的后续代码增量，具体测试和候选构建见 [实施记录](system-improvement-execution-20261001.md)。本文件不是实机或 G02 整包完成报告。

## 控制器与租约

- 项目固定的 Arduino core 在 classic ESP32 上使用 VSPI 作为全局 SPI；W5500 保留独立 HSPI，但六根网络信号/控制引脚须与全局 SPI 总线和各 CS 完全隔离。
- 在 S3/C3/C6 的同一控制器路径中，W5500 直接复用全局 SPIClass 与固定容量实际租约，不再创建指向同一硬件控制器的第二个 SPIClass。C3/C6 的既有 canonical 功能宏仍关闭 Ethernet，本增量没有扩大已发布的能力声明。
- 网络先启动和外设先启动都检查 CS/RST/IRQ 与总线线序；同一总线允许相同角色的共享信号，禁止控制脚别名、不同控制器绑同一根线、未知总线接管及 owner 隐式换配置。
- 锁序为调用方设备互斥 → SpiBusOperation → Arduino SPI 事务锁。ETH 后台任务使用同一个 SPIClass 自带的事务互斥，不反向取得外层生命周期锁。禁用 Arduino HAL 锁的构建明确返回 ETH_LOCKS_DISABLED，不以不安全并发冒充支持。

## 启停与失败

- 引脚、静态 IP 和注册占用先检查，再建立 SPI/回调/ETH。每个失败出口清理本次已取得的资源；事件注册失败不启动 ETH，静态 IP 设置失败不报告 DHCP 成功。
- stop 提供可失败结果；保留原 disconnect 接口适配调用者。ETH.end 是 void 且可能提前返回，因此必须检查 handle 和 netif 均为空，才能销毁独立 SPIClass 和释放租约。等待固定延时不再被当作驱动已停止的证明。
- ETH_STOP_PENDING 或 SPI_BUSY 保留传输对象与租约。传输状态/owner token 具有静态生命周期，适配器销毁不会产生悬空 lease；新适配器可以在之后重试清理，但不能越过未清理完成的驱动。
- 事件回调只访问静态状态，不再解引用可能被销毁的适配器。连接判断读取当前 link/IP 状态，不靠旧排队事件把新实例误标在线；状态读取与生命周期互斥，忙时不给出正常状态。
- 网络停用不会 end 共享总线或释放其他 SD/RFID/TFT/通用 SPI 使用方。独立 HSPI 停止只关闭自己的 SPIClass；共享总线的显式 end 仍拒绝 W5500 活动租约。

## 核心兼容边界

九个既有 canonical 环境均使用 platformio.ini 固定的 pioarduino/Core 3 构建依赖，不更换依赖版本。旧 Core 2 回退原先混用 Arduino/IDF host 编号、丢弃驱动与 netif 句柄，并不能可确认清理；该未验证分支不再声称兼容，而是无 I/O 返回 ETH_CORE_UNSUPPORTED。需要 Core 2 的外部项目须另行实现并验证对应生命周期，不通过关闭当前九目标的网络功能绕过门禁。

ETH.end 的内部等待没有由此变成硬实时有界；50/1000ms 等外层锁等待也不等于完整停止耗时。私有 SPI/静态状态和固定表有驻留内存成本；1000 次 mock 启停不能作为真实设备内存无泄漏、网络吞吐或长期运行证据。
