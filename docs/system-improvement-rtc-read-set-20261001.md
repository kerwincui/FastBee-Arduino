## 类型与时间语义

| 动作 | 固定参数 | 行为与上报 |
| --- | --- | --- |
| 35 RTC_CONTROL | start / stop | 保持既有启停语义，不写日期 |
| 36 RTC_READ | 空值 | 只读单次突发中的日历、CH 和时制；成功返回 YYYY-MM-DD HH:MM:SS，remark=rtc_calendar_unzoned |
| 37 RTC_SET | 必须显式选择 system-local | 复制执行时的系统本地日历，保留暂停/运行状态，写入 24 小时制并回读核验；仅轨迹，不作为数值数据上报 |

三个动作仅绑定 DS1302 外设，拒绝触发值替换、任意 JSON/模板和其它类型目标。空目标或错误目标不会自动改绑。保存、导入语义、预检与执行共享动作验证和 RtcAccess；读取也重新核验配置、运行状态和实例引脚，并在同一管理器递归锁内完成。

RTC 本身不包含时区。返回值不附加 Z、不冒充 UTC epoch；读取动作以选中的外设 ID 绑定平台文本属性，不发明推断的物模型字段。没有写入通用数值历史、数值条件/面板控制或跨动作模板缓存；这些展示/质量闭环仍需继续完善。

## 零代码使用路径

1. 配置并初始化 DS1302，核对接线、功能和外设启用状态；无效日历应先在现有外设操作页初始化。
2. 外设执行表单选择 RTC 日历读取或 RTC 复制系统本地时间，选择明确的 DS1302 目标。复制时间必须再明确选择来源，默认空选项，切换触发仍保留显式选择。
3. 校时前人工核对系统时间与配置时区。本动作不发起 NTP、不修改系统时间或充电；日历范围有效不代表时间源可信或已经同步。暂停的 RTC 写后继续暂停。
4. 如需上报只读日历，勾选上报，并在平台使用与 RTC 外设 ID 相同的文本属性。失败返回空值及明确原因，不填零、不复用上次成功值。
5. 先保存禁用规则、检查预检与参数，再由操作者决定启用。本次开发没有自动保存/启用现场规则、写现场时间、访问串口或控制电机。

## 失败与并发

- DS1302_HALTED：有效日历但暂停计时，不作为正在推进的采样。Web 手动读取仍可显示日历，并明确 quality=halted。
- DS1302_INVALID_DATA / DS1302_SYSTEM_TIME_INVALID：无效 RTC 或系统日期；写入前拒绝。系统年月日时分秒与星期在收窄前验证，失败的本地时间转换返回空结构，不暴露未初始化字段。
- DS1302_BUSY / NOT_READY / OWNER_MISMATCH 等：保留原访问边界，本次不操作 GPIO。50ms 仅为管理器锁等待上限。
- DS1302_WRITE_VERIFY_FAILED：回读与目标日历、暂停位、24 小时制或星期不一致。运行中的日历仅允许向前一秒用于跨秒/午夜；暂停日历必须精确一致。写入可能已经发生，不宣称回滚，也不自动重试。

系统本地时间复制成功只说明本次写后核验通过，remark=rtc_copied_system_local_unverified；不证明 NTP 来源、真实绝对时间、断电保持或走时准确度。读写均不创建后台采样/任务，不绕过现有执行调度和权限。

## 22:22 后续：HTTP 时间输入与 UTC 格式可靠性

主目录 TimeUtils 的 HTTP 时间入口此前仅比较时间戳下界，忽略系统设时返回值；32 位 millis 跨回绕、响应体延迟、非有限或溢出时间以及部分响应都可能形成错误的成功结果。本批修复仅在下一候选重新验收，不属于冻结 r7：

- 只接收 HTTP 200；JSON 成对时间、严格数字字符串、旧 XML 和仅 data.serverTime 的旧结构保持兼容。存在但无效/不完整的成对时间不得借 data.serverTime 掩盖，字符串数字前缀/内嵌 NUL/Infinity/NaN 拒绝。
- TLS 初始时间引导完成后才记录本次请求的单调发送时间，接收时间在响应体读完后取样；使用 uint32_t 差值覆盖 millis 单次回绕。保留既有四时间戳估算，拒绝反序服务端时间、处理时长超过往返时长、超时、非有限数值以及 long long/目标 time_t 溢出。
- timeout 必须为 1～65535 毫秒，对齐本机已安装 HTTPClient::setTimeout(uint16_t) 的真实边界，不再静默截断。该值是样本准入窗口，并不把 TLS 引导和各网络操作伪称为严格整体时限。
- 只有 settimeofday 返回 0 才返回成功并填写 outTimestampMs；其它情况清空输出参数但不把系统时钟设为 0。没有修改时区、RTC 电池或自动启动新的同步。
- ISO8601 的 Z 格式现在使用 gmtime_r；其它人读/日期/时间/RFC 格式保留配置的本地时间。格式化采用局部 tm 和重入转换，转换或 strftime 失败返回空文本，不复用全局 tm 或未初始化缓冲。此项不修复旧 parseTime 的 UTC 解析语义。

新增 test_http_time_validation 的 22 项编译/行为用例，加真实格式化/本地转换、RTC 动作与现有 Web 质量合同，合计 **82/82 PASS（58.322s）**；日志 artifacts/system-plan-g04-http-time-20261001-local-r3.log。主机执行抽取的生产方法与真实 ArduinoJson，替换网络、系统设时、tm 转换边界；覆盖 32/64 位时间范围、单调回绕、响应体拖延、TLS 引导、301、超时、设时失败及原输出清除。第一次 local-r1 的 Windows suseconds_t 测试桩编译失败保留，修正桩后 local-r2 的 23 项与上述扩大回归通过。没有真实网络同步或写入主机/设备时钟。
