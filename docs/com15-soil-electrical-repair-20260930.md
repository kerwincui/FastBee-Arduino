# COM15 土壤电流输入诊断与验收修复

目标：COM15 / ECM50-A / ESP32-S3-F16R8，MAC 14:C1:9F:C1:52:D8，地址 192.168.5.19。COM8 / .18 不在本次范围。

## 现场证据及边界

- 用户报告传感器供电 12.17V，AI1 端子约 9.18V，AI2 端子约 9.23V。棕线接电源正，黑线及两路 AI 负端接电源负；黄线接 AI1 正端，蓝线接 AI2 正端。
- 这些是用户万用表读数，尚无照片确认档位、测点及实物输入版本，也没有与 ADC 同步采样。不能把端子电压直接作为 MCU 引脚电压，更不能直接把它除以软件配置的 150Ω 当作独立实测电流。
- 本轮部署前身份核验通过；连续三轮实际 ADC 回读为 GPIO6 约 0mV、GPIO7 约 0–1mV，两路均 quality=disconnected、工程值为空。该质量码表示输入落在断线判定区间，不单独证明具体断线位置或器件损坏。
- 第二次只读检查的所有 HTTP 请求均成功；配置中 GPIO6/7 没有重复外设占用；有限日志尾部未出现 ADC 错误。这些检查不足以排除硬件、接触、输入前端或底层采样异常。
- 旧三样本湿度约 6.8%、温度约 23.3℃不代表当前输入；旧八小时失败、传输异常、物理灯反馈及测量准确性待验证事项全部保留。

## 已复现并修复的验收缺陷

原 test-soil-adc-device.py 在检查工程值前，无条件将理论工程值截到量程端点。若接口错误地返回 quality=valid 及端点数值，0、550、3300、9180mV 的 ADC 电压测试输入都能被误判通过。先增加回归用例，确认四个子用例失败，再修复。

- 独立检查校准参数、电流范围及有限数值；只允许原固件定义的半 LSB 端点容差。
- 报告明确标记 statusScope=configuration-and-signal-conversion-only 和 measurementAccuracyStatus=NOT_VERIFIED，记录目标 MAC、身份核验结果及逐轮采样时间。
- 增加部署后门槛 --require-current-diagnostics，校验实际 ADC 引脚、电压来源及计算电流的一致性。

## 固件诊断改进

/api/peripherals/read 增加 adcPin、pinVoltageSource 和 calculatedCurrentMa。电流计算与工程换算复用同一个函数，保留越界诊断值；calculatedCurrentMa 是由 ADC 与配置推算的电流，不是万用表实测。

本次不改变 150Ω 配置、增益、偏移、工程量程或质量门槛，不以用户描述的湿润程度设置校准值。该固件改进便于定位测点和换算问题，不构成现场电气故障已修复的证据。

## 土壤湿度缺失时显示 0%

按用户本轮追加要求，设备控制页的土壤湿度监测卡在缺失、断线或无有效湿度数据时显示 0%，同时显示“无有效数据（占位显示）”。有效的实测 0% 不带此提示。

- API、缓存中的真实值和 quality 保持原始含义，未将 null 或断线转换成真实的零湿度。
- 首次渲染、SSE 实时更新、重新渲染均使用相同显示规则；正常读数恢复后移除提示。
- DOM 保存 measurementValid、valuePlaceholder 和 quality，浏览器验收读取这些字段，不能因为看见数字 0 就把测量失败改成 PASS。
- 加载实际 main.css 后复现“hidden 提示仍显示”的样式覆盖问题，已增加专用隐藏规则并通过回归；各版 Web 的部署记录保留，最终以 web-deployment-v6 为准。

## 修复方案（2026-09-30，待实施）

以下按本轮固定源码与原始失败证据提出修复顺序。本节是方案，不是已经修复、构建、部署或实物通过的记录；现有八小时 FAIL 不变。当前工作区的 device-control/core.js、modbus-ctrl.js 已与 web-source-v6 不同，后续实现应先核对差异、保留已有改动，不能把工作区新逻辑当成本轮已部署证据。

### 1. 优先修正 SSE 连接生命周期与消息完整性

- 固定固件源码 SSERouteHandler.cpp 中，lastActiveMs 只在 trackClient 时赋值；维护代码却在 120000ms 后按该值关闭连接，后续发送没有更新它。这会使仍保持连接的客户端也进入超时关闭分支。先以保持正常发送/确认的连接做最小复现，再改为实际传输进展或底层 ACK/队列状态驱动的超时管理。不能简单在每次调用 send 时无条件刷新时间，掩盖真正堵塞的客户端。
- broadcastModbusData 对超过 512 字节的 JSON 使用 substring 截断后发送，存在不完整 JSON 风险。改为按完整记录拆成独立合法 JSON 事件、限制每包条目并保留顺序；单条超限需显式记录错误并安排受控快照恢复，不能静默截断或无边界增大缓冲。是否在本次运行触发了该分支尚未证明。
- 验证：健康连接跨过原 120 秒期限仍可用；真实停止确认/积压的连接能释放；大消息可逐包解析、无丢项；断开重连后恢复完整状态。上述代码路径不能直接被宣称为全部 81 次设备传输失败的根因。

### 2. 修复页面刷新、静默停更和继电器读回恢复

- 已部署 Web 源码 loadDeviceControlPage 在请求完成前清理运行状态并替换为 loading。改为保留卡片结构，先构建新快照、校验后再替换；失败显示明确的通信失败/过期状态，旧值仅作为带时间戳的历史值，不计为新鲜有效测量。
