## 当前支持

2026-10-04 17:22后继来源修复已合入待集中回归：读取已保存外设driver并按真实通道metadata确认摄氏温度，DHT湿度和其它非温度物理通道不能靠错误单位标签进入控制；保留DS18B20/NTC及显式工程转换，后者不代表物理校准已验证。I2C属性别名按执行器默认通道解析，初次source binding与epoch捕获在同一外设递归锁内。DHT表单切换/收集同步固定单位；冻结旧binding负例与完整runtime永不LOW回归已准备，尚未测试。下列较早本地证据不继承至本批。

新增持续动作 39 `ACTION_THERMOSTAT`，以已有 Observation 温度缓存驱动独立温控规则。用户通过外设执行表单选温度来源、制热/制冷、停止阈值、启动回差、最小开/停秒数、最大样本年龄、启动/故障/恢复策略。表单中的“设置独立温控触发”只更新未保存表单并取消启用；仍需用户保存并确认接线后启用。

- 仅支持已启用的专用原生数字输出、低电平吸合、上电 HIGH、无反相/蜂鸣器/扩展器。复用已有 ControlOutput 的 inactive-HIGH 和互斥所有权契约，不更改该类。与 H1 RESET/OE 共用四个 claim；实际不足/冲突时拒绝控制器接管。
- 来源必须为已保存的本地摄氏采集动作，且同一缓存键只能有一个保存的生产者，该生产者须启用、固定参数。第二条同键采集规则即使禁用也不接受，因为禁用规则可能被手动执行。页面只列显式单位为 `°C`、`℃` 或 `C` 的本地通道，不猜测 Modbus 或 UART 数据的物理含义。
- 温控规则只允许单动作、单个 1 秒间隔触发，无接收值替换、动作延时、屏幕控制、脚本或数值历史。保留动作 ID，不改变旧动作含义。
- 实际检查沿用框架每 1 秒的高优先级任务；250ms 是防止重复调用的最短间隔，不是实时响应保证。检查先于普通定时器/工作队列的内存暂停门禁，SEVERE/低DRAM时请求关闭。

## 控制与安全语义

制热在 `停止阈值−回差` 及以下开启，到停止阈值关闭；制冷在 `停止阈值+回差` 及以上开启，到停止阈值关闭。回差内保持原状态。正常转换遵守最小开/停时间；无效、失鲜、未来时间戳、非有限数、单位不符、来源修订变化及资源/输出故障请求 HIGH，绕过最小开启时间。

启动先确认 HIGH，必须取得会话开始后的有效新样本，并经过完整最小关闭时间，才可能开启。缺失启动样本不当作数值零。自动恢复仅适用于可恢复的数据/内存故障，需要故障后的新样本和最小关闭时间；人工策略保持关闭直到停用再启用。输出失败和来源修订变化不会自动恢复。

除 Observation 修订外，会话保存生产者规则 ID、目标和完整采集参数。采集规则停用、删除、替换、倍率/偏移等变化立即请求关闭并锁定。无关规则图修改不重置温控驻留时间或解除人工故障锁定。控制配置变更、规则停用/删除会先释放为 HIGH；保存失败按现有事务恢复规则，不能把失败保存说成停用成功。

会话还在原生输出准入时捕获 `SensorConfigEpoch`，每次输出前在外设配置锁内复核。任何导致该全局版本递增的外设配置变化（包括其它传感器配置）都会保守锁定关闭，需要检查后停用再启用；不能用换接引脚/校准后的新样本自动恢复旧温控会话。

输出写入只在持有专用 claim 时允许；ControlOutput 复核目标类型、引脚、生命周期、所有权及引脚反馈。HIGH/释放未确认时保留原 owner 和资源占用，后续仅重试安全 HIGH/释放，绝不因为析构或重试而恢复 LOW。配置恢复待重启/加载失败同样要求关闭。普通 GPIO 动作不能覆盖已认领的输出。

首次 Claim 登记后HIGH失败的部分准入，也进入只重试安全释放的路径，保留原失败会话防止自动重新接管。框架关机必须先调用 `shutdownThermostats()` 设置永久准入栅栏并释放HIGH；失败时应保留任务运行以继续退役，不能先停止任务留下LOW。成功关机后的同一进程不自动重新准入，需完整重启。

GET 规则列表的 `thermostats` 是只读诊断快照，包含 phase、padConfirmed、outputOn、retiring、checkAgeMs 等；读取失败返回 null。页面区分“规则已停用”和“关闭未确认”，包含已删除规则遗留 owner 的全局提示。手动执行动作 39 只读取状态，不开启、不重启控制器、不解除故障。所有引脚反馈都是 MCU pad 读回，`physicalFeedback=NOT_OBSERVED`，不能称继电器触点或真实负载已确认。

## 配置接口

动作 39 的 `actionValue` 固定字段：`sourceRef`、`mode` (`heat`/`cool`)、`setpoint`、`hysteresis`、`minOnSec`、`minOffSec`、`maxAgeSec`、`recovery` (`manual`/`fresh`)、`startup="fresh"`、`fault="off"`。未知/缺失字段、错误类型与越界拒绝；界面负责生成 JSON，使用者无需手写 JSON 或脚本。

`ThermostatConfig.h` 的 `parseThermostatConfig` 与 `validateThermostatRule` 为纯只读共享验证入口。目标类型由 `PeripheralActionContract` 统一判断；普通 CRUD、启用和运行时再次验证。迁移可保留禁用草稿，启用时必须满足目标上的唯一有效本地摄氏生产者约束。
