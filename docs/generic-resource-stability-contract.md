# 通用零代码固件：资源与稳定性验收约束

更新：2026-09-23。适用于“功能配置 → 外设配置 → 外设执行 → 联动”的公共链路。本文区分验收要求与已完成实现，不表示所有要求已通过。

## 产品与兼容性

- 保持一个固件产品、一套配置及执行模型。芯片编译目标描述硬件能力，不代表不同产品档位；不改动 `unified_flags` 来制造新的产品版本。
- 普通功能按用户配置启用；设备屏幕能力限 ESP32-S3。引脚、总线地址、传感器参数和执行规则由配置表达，生产逻辑不绑定测试用 COM 口、IP、MAC 或外设 ID。
- 换板后保留配置的语义，重新校验目标芯片的引脚、总线和资源能力。不能保证有限 RAM 能容纳任意数量、任意并发的配置；超出能力必须明确拒绝或显示运行保护状态，不能保存成功后静默丢失规则。

## 必须满足的公共行为

| 环节 | 验收要求 |
| --- | --- |
| 配置准入 | 新建、修改、导入、启动加载复用一致的结构与容量校验；检查外设、动作数量、字符串长度、引用以及组合资源开销。失败时说明原因，保留原有效文件及运行配置。 |
| 内存口径 | 区分内部可按字节访问的 DRAM、最大连续块与 PSRAM；涉及网络、任务及内部资源预留时，不能用总空闲堆或不可按字节访问的内存代替。 |
| 分配生命周期 | 关闭的可选功能不提前申请专属动态缓冲；首次使用、重复启停、失败回滚均有明确所有者。已有执行的完成状态在压力下仍应可记录。 |
| 峰值预算 | 组合考虑常驻外设/规则、首次执行历史、任务栈、日志、Web 响应和网络缓冲。静态文件本身虽在 Flash，文件对象、响应对象、TCP 队列仍占 RAM。预估不能替代运行时分配失败检查。 |
| 并发控制 | 根据实际可用资源限制同时在途的请求与执行，等待队列有上限；公平恢复，不长期饿死外设采集。不能将无限积压移到另一个队列。 |
| 压力恢复 | 显示限流/暂停、原因与恢复条件；不因一次资源不足持久关闭用户规则。未获准的手动或电机动作不得在恢复后无提示重放。 |
| Web 反馈 | 配置保存成功、运行生效、操作获准和操作完成分别反馈。传感器旧值标记时间/过期，不能以请求 200 或保护恢复代替有效数据。 |
| 持久化写合并 | 周期性感知写（历史数据落盘、日志缓冲 flush）按窗口合并并对齐到同一 Flash 写窗口，不按采样或轮询频率写 Flash；显式保存、配置写入和受控停用前的 flush 保持即时。历史数据是内存缓存加周期落盘：断电最多丢失最近一个落盘窗口（`PointHistory::FLUSH_DEADLINE_MS`，3 min；日志 flush 活跃时合并窗口最短 2 min 即可能落盘）内未持久化的采样，重启后只恢复到最后一次成功落盘的快照。Web/API 读取的是内存缓存，不受落盘窗口影响。 |
| 测试证据 | 检查字节完整性、延迟、峰值内部 RAM、连续块、后台执行与恢复；主机测试、固件构建、实机短测及长期运行分别记录。保留失败，不能靠放宽时限或去掉功能取得通过。 |

## 后续闭环顺序

1. 用可复现的分配/发送故障验证公共 Web 生命周期，记录断点、已传输字节与关闭原因，再部署有针对性的修复。
2. 将本轮已实现的外设执行配置校验与事务边界部署验收，检查真实配置保存、导入待重启、重启回读及故障恢复；其他配置管理器仍需各自验收，不据外设执行结果推断全系统已完成。
3. 在现有公共资源管理中补充组合预算与有界并发反馈，覆盖首次执行和功能启停。估计不足时明确标为估计，不承诺精确的剩余可配置数量。
4. 用相同的外设配置/执行机制覆盖不同芯片、带/不带 PSRAM、容量边界、重复导入、驱动初始化失败、浏览器突发和恢复。实际部署按目标逐台验收。

本轮并行审查补充：[配置容量与事务](../artifacts/r14-config-capacity-review.md)记录修复前问题，后续实现及测试见[配置安全结果](../artifacts/r14-config-safety-result.md)。[HTTP 生命周期](../artifacts/r14-http-lifecycle-review.md)用真实函数复现了关闭连接时 `tcp_close` 返回 `ERR_MEM` 后强制中止、丢弃排队正文的组合；尚无现场证据将其认定为 C3 本次截断的唯一原因，实际修复与部署以发布记录为准。

配置错误反馈：`CONFIG_MEMORY_PRESSURE` 表示当前内部可用/连续内存或保守组合预算不足；`CONFIG_RULE_COUNT`、`CONFIG_TRIGGER_COUNT`、`CONFIG_ACTION_COUNT` 表示既有数量上限；`CONFIG_DUPLICATE_ID` 表示重复规则标识；`CONFIG_LOAD_FAILED` 表示启动配置未完整加载，禁止覆盖原文件；`CONFIG_PENDING_RESTART` 表示新配置已经提交，需重启后继续修改。这些状态不代表规则被自动删除或持久关闭。

本轮发布：两目标 r14 构建源码稳定，COM16 应用分区剩余 260,048 字节、C3 剩余 266,496 字节；分别保留 11 / 9 个非 Web 现场文件。HTTP 最后字节等待 TCP 确认、成功 JSON 减少重复缓冲、Web 静态请求排队与正文期限均已部署，未修改 SDK。C3 与 COM16 均实测无效导入拒绝、原文件保留、相同配置提交、单次重启和重启后规则回读；中间发生的传输失败仍保留为历史证据。没有执行手动外设或电机动作，也没有进行新的 24/72 小时长测。
