# 通用 Modbus 电机协议配置与 YF-53 核对记录

## 实现范围

统一通过 MotorControlService 调度 Web、触摸屏和规则请求，不按型号分支执行。
YF-53 仅为配置弹窗中的显式预设，不自动改从站地址、波特率、UART、实体接线或行程。
本轮为本地代码和测试改动，没有部署、登录设备、改变参数、扫描地址或发送电机动作。
已有设备的读回超时仍待实机定位，不能凭预设或本地测试判定电机已修复。

当前通用范围是单个无符号 16 位寄存器参数、有限脉冲运动：

| 配置项 | 支持范围 |
| --- | --- |
| 读回功能码 | 03 保持寄存器、04 输入寄存器 |
| 写入功能码 | 06，或 16（0x10，每次写一个寄存器） |
| 读写地址 | 速度、脉冲数分别配置读回地址，写入地址保留 motorRegs |
| 动作映射 | 正转、反转、停止各自的地址和值；允许共用地址但值必须不同 |
| 零值 | 地址 0、停止值 0 均合法，不用 truthy 默认值替换 |
| 安全条件 | 已确认有限脉冲模式、完整且新鲜的参数读回、正脉冲数、现有软限位和停止优先 |

未实现 32 位/浮点/有符号多字参数、独立运行状态或编码器反馈、伺服使能握手、
多阶段厂商动作、CAN、脉冲输出或私有串口协议。不能称为支持所有电机。
这些协议需要增加明确的数据类型、状态机和测试，不得通过裸 HEX 或取消启动保护绕过。
串口沿用现有 Modbus 配置，预设不代表已经核实现场格式、波特率或收发器类型。

## 配置结构

以下是合成通用示例，不是任何现场设备的推荐参数。不要直接用于实物：

    {
      "deviceType": "motor",
      "motorRegs": [100, 100, 100, 101, 102],
      "motorDecimals": 0,
      "motorProtocol": {
        "version": 1,
        "readFunction": 4,
        "writeFunction": 16,
        "speedReadRegister": 200,
        "pulseReadRegister": 201,
        "forwardValue": 17,
        "reverseValue": 34,
        "stopValue": 0,
        "finitePulseMove": false
      }
    }

finitePulseMove=false 时仍可读参数、设置参数、尝试停止，但不能启动。
只有设备协议和实际工作模式确认按脉冲数结束运动后才可启用。
新建自定义设备和重新载入 YF-53 预设均不自动启用该确认。
现场工作模式需要单独核对，不能仅根据型号替用户勾选。该声明不能代替硬件限位或急停。

缺少 motorProtocol 的旧配置继续采用原 FC03/FC06、原读写地址和规则值语义。
显式配置必须具备全部字段且版本为 1；非法配置在保存 API 返回 400，加载时禁止控制，
不悄悄回退成可执行默认值。参数地址不得和动作地址重叠。
新字段经过 Web 保存、协议摘要、完整读取、两个配置加载路径和文件保存完整往返。

选择显式配置或修改动作语义后，控制引用会变化；已有屏幕组件需要重新选择对应电机。
这样旧缓存、排队动作和旧界面引用不会误控新映射。
明确配置下，规则的正反转/停止使用映射动作值，不再把旧规则数值当作厂商命令字。
既有软限位规则中的脉冲步数计算保留；位置只是命令估算，不是反馈坐标。

## 厂商资料证据

来源为用户提供的三个原件，均未修改：

- 3440420115YF-53产品说明书.pdf，物理第 8、11 页（印刷第 7、10 页）。
  SHA256: f3194438efb24e16058ac9ac794928d8941826994e3b165ac1cdc1e7d92798e1
- 3440408323YF-53 MODBUS通信协议(1).xlsx，Sheet1 B11:B18、D17、B21:B25、A27:A28。
  SHA256: f7332d45fe29de4c3ee04d9a21fda57b9fb3269d6412e3b1ad3a5c57ebf8410c
- 3440410309YF-53改地址.doc，结构化读取 OLE Word 文本。
  SHA256: 30c18e792341b403eb810c8c534e34b8fa0304d8f549c636c983d62023f227ed

PDF 明确支持 03、06、0x10；XLSX 的完整指令和 PDF 第 11 页图表一致：

| 用途 | 功能码 | 零基地址 | 写入值 |
| --- | --- | --- | --- |
| 正转 | 06 | 0 | 1 |
| 反转 | 06 | 1 | 1 |
| 停止 | 06 | 2 | 1 |
| 速度 | 03 / 06 | 5 | 参数原始值 |
| 脉冲数 | 03 / 06 | 7 | 参数原始值 |

因此，03 读取 5/7 本身与厂商资料一致，不能把历史超时直接归因为寄存器写错。
原例使用从站 1；D17 的改址例写入 8 不证明当前设备就是从站 8。
DOC 说明上电时从通信口自动发送当前地址三次，不意味着 ESP32 的 USB 调试串口能看到它。
默认 9600/8N1 也不证明现场设置未改变。

资料矛盾：PDF 第 9、10 页的一般例子存在数量、字节数和说明不一致；
XLSX 的部分引导例子也与专用指令表不一致。预设只采用互相印证且 CRC 正确的完整报文。
13 个完整帧已与生产代码生成的请求逐字节比对。测试中的改址/波特率帧只在内存执行。
不依据说明书的非标准广播范围放宽现有地址限制。

## 超时定位与安全验收

1. 保持原保护，确认同一个控制器的型号、RS485/RS232 电气接口、真实地址和串口格式。
2. 在断开负载或具备可靠硬件急停/限位的条件下，由现场人员确认接线和收发方向。
   不把 RS232 电平直接连接 ESP32 GPIO，不给未知接线指定电压。
3. 核对所选 UART 的 TX/RX、转换器、DE/RE/自动方向及地线。先前正转成功不能排除回包链路问题。
4. 后续单独安排有界只读测试，或用隔离的已知正常主站验证同一 FC03 请求；
   不让两个主站同时占用总线，不盲扫地址、改址或反复重发动作。
5. 保存 TX/RX、超时阶段、CRC/异常码，区分没收到字节、帧不合法和明确的 Modbus 异常。
   新错误例：speed s8 FC03 r5 TIMEOUT; pulse s8 FC03 r7 TIMEOUT。
6. 参数读回通过后，再分别验收低速短行程正转、停止、反转和边界保护。
   每次动作只发一次；写回 ACK 不等于已运动或已停止。软件软限位不能替代机械保护。

本轮未执行现场检查，未证明接收链路恢复，未验证负载或连续 24 小时稳定性。

## 独立 RS485 只读对照工具

scripts/test-modbus-serial-readback.py 用于隔离主站的只读比较，不替代电机控制服务。
支持从站 1..247、FC03/FC04、显式零基寄存器、波特率和 8N1/8E1 等格式，
不绑定 YF-53。每个地址只读一个寄存器；最多 8 个明确地址，不提供扫描、
写参数、动作、裸报文或重试入口，首个失败后不再发送后续请求。

默认仅生成报文和报告，不打开串口。例如在仓库根目录执行：

    & "$env:USERPROFILE/.platformio/penv/Scripts/python.exe" scripts/test-modbus-serial-readback.py --slave 8 --function 3 --register 5 --register 7 --out artifacts/independent-readback-plan.json

--list-ports 只枚举 USB 元数据，不打开任何串口。实际执行还需要同时提供
--execute、--port、与枚举结果完全一致的 --expected-hwid，以及
--confirm-isolated-rs485。该确认表示机构已处于安全状态、所选设备确为自动方向
USB-RS485 适配器，并已断开屏幕及其他主站。USB 芯片型号本身不能证明适配器用途。

不能将 ESP32 的 USB 调试端口作为独立 RS485 适配器。本次用户确认目标是 COM8，
其 USB 身份为 Espressif / E8:3D:C1:F7:65:44；其他 COM 口属于其他设备，不能借用。
工具拒绝 Espressif USB 端口，不通过取消检查把 Modbus 报文写入 COM8。

报告保留原始 TX/RX 十六进制、异常码、请求回显、CRC/地址/长度错误、零回复和
串口 I/O 异常。发送异常保留“已尝试、发送接受字节数未知”，不伪记为未发送。
既有报告不可覆盖；只读成功也只标记读回通过，不标记物理运动或长期稳定性通过。
实际接入仍需现场人员确认，打开串口可能受驱动及适配器握手行为影响。

离线回归：

    & "$env:USERPROFILE/.platformio/penv/Scripts/python.exe" -m unittest test.unit.test_modbus_serial_readback test.unit.test_serial_diagnostics_contract -v
