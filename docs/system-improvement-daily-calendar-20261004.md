# 每日时间点的启动内日期去重

日期：2026-10-04。针对计划§8.1/§9.3的日历时间跳变影响已合入；r45真实方法15项通过，实际CRUD/保存/加载四profile回归亦通过，r47序列化去重后的配置路径再次通过。原r45整体FAIL及修订夹具r46各自保全；完整候选尚待，设备输出和现场校时均NOT_RUN。

此前每日时间点只检查本地日历的HH:mm，再用单调时钟抑制60秒。时间回拨后再次进入同一天的目标分钟，或错误日历停留目标分钟超过60秒，可能重复接纳同一每日动作。原代码没有按日期记忆成功接纳的日程；间隔触发是另一条单调时钟路径。

每个每日HH:mm日程现在保存本次启动内已接纳的最大本地日期`YYYYMMDD`。只在当前日历有效、精确命中HH:mm且日期大于该水位时尝试入队；同日或回到更早日期不重复。相同规则内重复的同一HH:mm条件共享接纳日期，分别配置的其它日程保持独立。既有60秒抑制、轮转游标、运行中/Modbus/资源退避仍保留。

| 情况 | 行为 |
| --- | --- |
| 同一天内回拨后重访目标分钟 | 已接纳日不再执行；不是再次发送后声称幂等。 |
| 跨午夜到后一天 | 新日期在目标分钟可以接纳一次。 |
| 向前跳过目标分钟 | 不补跑错过的分钟；下一天仍按新日期匹配。 |
| 资源/队列拒绝 | 不消费日期、触发计数、时间戳或轮转游标；仍在目标分钟内可重试。离开该分钟后不排队补跑。 |
| 扫描后、接纳前时钟改变 | 再读取日期与分钟；不再匹配则放弃本次候选。入队后的异步执行可晚于该分钟，不能因此假称未执行或回滚。 |
| 成功接纳后动作失败 | 保留已接纳日期；不自动重复可能已部分执行的动作。 |
| 同时发生两个定时扫描 | 零等待守卫覆盖扫描、入队和运行字段提交，第二次直接跳过。 |
| 修改名称、动作或重排相同HH:mm | 保留相同日程日期；不能通过普通编辑清除当天去重。 |
| 停用后重新启用 | 保留水位。只有创建新日程、更改HH:mm、重新创建规则或重新加载/启动会建立新的运行状态。 |

一次错误的大幅前跳若已经在未来日期接纳了日程，校正回过去后会继续抑制，直至日期超过水位。确需重置时必须先核对已执行输出，再通过重新启动或明确更改日程等建立新状态。不会自动忘记未来接纳事实以补跑旧日程。

这是启动内的重复抑制，不是掉电后永久只执行一次保证。水位不写文件、不从导入JSON或调用者提供的运行字段恢复；配置重新加载/重新创建也会重置。日期本身验证年月日、闰日、时分秒和算术范围，但不证明绝对时间准确。仍按已有策略使用有效本地日历，不增加`synced=true`强制门槛；显式启用RTC启动采用可能让原先等无效系统时间的每日规则开始匹配。

新增状态为每个触发器4字节加管理器一个原子标志，不新增常驻集合或后台任务。候选扫描局部增加日期和分钟字段；完整Flash/RAM门禁与目标板实测仍需统一执行。

15组Host回归执行真实`checkTimerTriggers`，覆盖同日/跨日/回拨、跳过分钟、前跳纠正、队列拒绝、过期候选、无效日历、时钟不可用、间隔不变、重复条件、修订变化、并发扫描和守卫释放。实际CRUD/保存/加载夹具另覆盖同日程迁移、停启、输入运行字段拒绝、持久化不带水位。以上指定输入的局部Host通过，证据见r45和r47 focused独立保全目录；不代表设备时序、真实内存或实物验收。
