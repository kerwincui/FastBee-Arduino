## 一、审核结论与状态口径

现有实现值得保留，但原文“8 项已完成”的结论不成立：部分任务被重复计数，测试通过被扩大为实物通过，部分修复只有文案或断言变化，另有已实现的功能被误列为尚未实施。**本轮应在已有能力上收敛产品界面，修复已确认缺陷，补齐可运行的回归与实物证据。**

主要结论：

1. **Web 需要重构。** 当前源码已将保存栏移入配置页，但仍保留长表单、隐藏的布局编辑器、独立历史保存、组件“应用设置”和重复天气入口。用户截图反映的混乱尚未整体解决。
2. **亮度、蜂鸣器、天气不能标记完成。** 最低亮度映射重复抬升；触摸提示音忽略时长配置；息屏路径在关闭蜂鸣器失败时仍清除重试标记；天气状态接口显示的 30 秒重试不等于调度器实际重试。
3. **存在编译阻断。** RGB 和 SPI 显示后端读取 `_config.touch`，实际 `DisplayConfigParams` 没有该字段。启用相关后端时需先修复这一契约错误，再验证完整固件构建。
4. **导航、趋势、电机已有主体实现。** 应保留已有五项导航、手势仲裁、趋势坐标、公共电机服务和防重复机制，补齐缺失功能与实机验收，避免重复重写。
5. **测试与发布门禁有缺口。** 原 28 项测试通过；新增定向回归出现失败和编译错误。现有发布目录按放宽后的 318 KiB 预算通过，按原 315 KiB 预算失败。
6. **目前不能证明新版本已在设备上解决现场问题。** 历史部署、修改后的 API 快照、Web 样式变化和主机测试分别只能证明其对应范围。

状态采用以下口径，不再给出混合完成百分比：

- **保留**：当前代码存在且有相应本地证据，继续复用。
- **部分实现 / 待完善**：主体已存在，仍有明确功能或质量缺口。
- **重新打开**：原标记已完成，但发现缺陷、证据不足或与最新需求冲突。
- **本地通过 / 已部署 / 实物通过 / 长期通过**：分别记录版本、时间和证据，不能互相代替。

## 二、当前质量问题与证据

### Q01：预览和编辑的职责仍未收敛

- [screen-panel.html](../web-src/pages/screen-panel.html) 的 `.sp-save-bar` 当前已位于 `#sp-config` 内，应保留这个改动；截图中预览仍有保存栏，说明截图与当前源码不能混作同一版本证据。
- 第二个 Tab 仍叫“配置”；`#sp-content-list`、页面工具栏、折叠的 `#sp-layout-editor`、天气/历史/全局设置形成多套重复操作路径。
- `#sp-history-save` 独立保存；[screen-panel-model.js](../web-src/modules/runtime/screen-panel-model.js) 属性区仍生成 `#sp-card-apply`“应用设置”。用户仍需理解不同保存层级。
- 组件库通过 `data-sp-add` 点击添加；画布已有移动/缩放，不等于已经支持“从组件库拖入画布”。
- [screen-panel.css](../web-src/css/screen-panel.css) 的 `.sp-body` 顶部 padding 为 0。当前增高到 72 px 的 `.sp-pagination` 是 Web 画面外的分页圆点区；48 px 的 `.sp-page-tab` 是编辑器页签，均不能证明实体底栏热区已修复。
- 样式复用还需核对颜色变量与主题回退，统一到现有 `--bg-card`、`--border` 等变量，避免引入未定义变量造成局部失去背景或边框。

**决定：** 保留保存栏归属修正和画布模型，整体重组页面；移除重复入口，不继续在长表单上堆叠折叠块。

### Q02：外设执行的合并卡片只占半宽

[modals.html](../web-src/pages/modals.html) 在本来已是两列网格的 `.pe-rule-options` 内新增单个 `.pe-data-display-card`，内部又套两列网格，外层子项没有跨满两列。

本次用当前 HTML/CSS 做浏览器布局测量：1440 px 视口中，外框 900 px，内部卡片仅 426 px；右侧空置，选项被挤在左半边。390 px 视口会单列显示。证据：[modal-grid-audit.log](../artifacts/touch-plan-audit-20260924/modal-grid-audit.log)。这只是局部布局测量，未代替完整弹窗交互验收。

**决定：** 改为一个边框容器加一个 2×2 网格；保留三个复选框和一个记录管理按钮。触屏可见的帮助不能仅放在 hover 的 `title` 中。

### Q03：全局外观已有数据链，但生效问题尚未定位

[screen-panel.js](../web-src/modules/runtime/screen-panel.js) 的 `_spApplySurfaceTheme` 优先使用页面 `themeId/background`；模型会保留页面覆盖。[ScreenPanelManager.cpp](../src/core/ScreenPanelManager.cpp) 已校验并写入快照，[ScreenRuntime.cpp](../src/screen/ScreenRuntime.cpp) 已读取配色/背景并参与绘制更新判断。

因此不能断言“固件未实现主题”。需逐项核对页面覆盖、未提交草稿、保存版本与运行应用版本、Web 缓存以及实际部署产物。UI 的 `geometry/gradient` 与接口的 `grid/soft-gradient` 映射也应继续受测试保护。

**决定：** 页面默认继承全局；独立外观必须清楚标识并能恢复继承。保存后展示实际应用结果，保留用户有意设置的页面覆盖。

### Q04：亮度语义与能力契约存在实质问题

- [ScreenBacklight.h](../include/screen/ScreenBacklight.h) 先将 0–9 归一化到 10，再计算 `1000 + level × 90` 的保底映射；最低输出因此是 48/255，约 19% 电气占空比，并非注释描述的约 10%。当前测试对 48 的断言不能证明产品语义正确。
- Web 定向测试期望保留逻辑 0，当前规范化结果为 10，源码与压缩版均失败。需先定统一语义，再修实现和测试，不能只改断言适配现状。
- [RgbDisplayBackend.cpp](../src/screen/RgbDisplayBackend.cpp) 和 [SpiTftDisplayBackend.cpp](../src/screen/SpiTftDisplayBackend.cpp) 的 `_config.touch` 在实际 [PeripheralConfig.h](../include/core/PeripheralConfig.h) 中不存在。触摸能力应依据真实后端及初始化状态推导。
- 当前板级样例 `backlightActiveHigh=true`，而[历史工业 UI 记录](touch-screen-industrial-ui-20260923.md)写明本机实测要求 `false`。这属于相互冲突的历史证据；本次未核对实机，不能宣布 true 或 false 是最终答案。

**决定：** 用户滑块保持 0–100 的逻辑范围；0 代表最低可见档，100 代表最亮，只有显式息屏关闭背光。后端只做一次最低可见值映射和一次极性转换，实际电气值不宣称为测量后的光学亮度。

### Q05：蜂鸣器“已修复、可配置”结论需要撤回

- `touchBuzzerDurationMs` 配置为 20–150 ms，但当前 `touchFeedback` 忽略 `config`，使用固定 `BUZZER_PULSE_MS=80`。相关测试改为断言固定 80 ms，未验证配置是否生效。
- 息屏分支调用 `setBuzzer(false)` 后不检查结果，直接 `buzzerNeedsOff=false`。若该次 I2C OFF 失败，后续关闭重试可能被丢弃。这是明确的代码缺陷，但不能据此认定所有启动常鸣的根因均已找到。
- RGB 后端已有初始化时先写安全电平、再切换方向以及结束时关闭的逻辑，应保留。仍需检查初始化半途失败、MCU 单独复位后 CH32 输出保持、位掩码冲突、总线恢复和任务退出路径。
- 当前 CH32 接口仅支持 `setBuzzer(bool)`，不具备真正的音量控制。缩短时长不等于降低音量。

**决定：** OFF 成功前保留关闭责任；关闭失败期间禁止新 ON，继续限频重试并在总线恢复后先清除旧输出。软件不能在总线永久失效时保证外部锁存输出一定关闭；此类硬件是否需要自身定时关闭机制须单独验证，不使用“任何情况绝不长鸣”的无依据承诺。

### Q06：天气状态文案改变不等于自动恢复

[RemoteResourceManager.cpp](../src/protocols/RemoteResourceManager.cpp) 已翻译 NTP 错误，但状态接口在任何错误时都返回固定 `retryAfterMs=30000`；实际 `collectWeather()` 仅把两类网络错误作为暂时故障，NTP 错误仍可能按正常刷新周期延后。设置 30 分钟刷新时，界面“30 秒后重试”可能对应实际等待 30 分钟，且未找到校时成功直接唤醒天气的闭环。

现有天气测试读取 `artifacts/touch-optimization-20260922/postdeploy-api.json`。原计划明确记载修改了该快照；这份文件不能作为“新版本已在设备上修复”的证据，也不能验证 worker 是否执行请求。[卷边复核](touch-screen-roll-edge-20260923.md)还记录过 `Insufficient memory for weather request`，天气问题不仅涉及 NTP。

**决定：** 使用可测试的错误分类与真实调度状态；区分自动重试时间和手动刷新限频。保留原始采集记录，合成案例放测试夹具；无法恢复原始记录时明确标为不可用于实物验收，重新采集新版本证据。

### Q07：保存机制存在，但不是完整事务

`_spSaveAll` 已按天气、历史、布局顺序协调并报告部分失败，应继续复用。问题包括：属性输入尚需单独应用、部分表单不参与脏状态、历史仍可独立保存，以及 `handleSaveHistoryConfig` 没有与布局相同的 `expectedRevision` 校验。

**决定：** 一个主保存按钮协调同一个草稿；所有资源先校验再写入，补历史冲突保护。多个配置文件串行成功不等于原子事务；在复用现有存储能力前提下明确中途失败、重试和断电恢复语义。

### Q08：资源预算被放宽，不能当作质量完成

当前修改把屏幕额外预算从 35.5 + 0.5 KiB 改为 37 + 2 KiB，总预算从 315 改为 318 KiB，注释仍描述另一组数值。对当前 `data/www` 只读检查得到：

| 检查方式 | 结果 |
| --- | --- |
| 当前 318 KiB 门禁 | 通过：总量约 316.6 KiB，首屏约 63.2 KiB，57 个文件、54 个 gzip 文件 |
| 原 315 KiB 总量门禁 | 失败：316.6 > 315.0 KiB |
| 原屏幕懒加载分配 | 失败：36.0 > 35.5 KiB |
| 原基础/共享分配 | 失败：280.6 > 279.5 KiB |

证据：[published-web-budget-audit.log](../artifacts/touch-plan-audit-20260924/published-web-budget-audit.log)。本次没有重新发布 Web；该报告描述已有产物目录，不能证明它与全部当前源码一致。

**决定：** 先通过删除重复界面和复用样式回到原预算；如确有新增能力需要预算变更，另附分项体积、Flash/DRAM 余量和目标设备负载依据，再作明确决策。

## 三、已批准的目标使用方式

### 3.1 两个一级 Tab：预览 / 编辑

保留菜单顺序“外设执行 → 通信协议 → 设备屏幕 → 设备大屏”。通信协议继续只展示其协议配置，不恢复远程资源 Tab。

**预览：** 默认展示设备已保存并应用的页面模型与实时状态，可切换页面、刷新数据、进入“编辑此页”。提供紧凑的在线/应用版本状态；没有保存、导入、导出、布局属性或组件工具。预览由相同配置生成，不宣称是设备逐像素视频截图；数据过期、断线和未应用要明确标识。草稿效果放编辑画布，避免预览里再增加一套已保存/草稿选择。

### 3.2 基础组件与对应配置

| 组件 | 用户主要配置 | 交互与边界 |
| --- | --- | --- |
| 数值 / 状态 | 已有数据源、标题、单位、小数位 | 显示质量和更新时间，卡片无动作 |
| 趋势 | 数值源、标题、单位、量程；已有记录能力 | 默认最近十点；共用原历史服务，不另建采样任务 |
| 心知天气 | API Key、城市；默认 30 分钟，可选 15/30/60 分钟 | 直接配置服务；没有供应商选择、通用天气来源、鉴权/字段映射/预报 |
| 时钟 | 时间/日期显示方式 | 使用设备时间；未同步显示原因，不借浏览器时间伪装已同步 |
| 电机控制 | 已有电机、速度/脉冲默认值与范围 | 仅明确按钮操作；共用电机服务和权限 |
| 外设执行 / 开关 | 有权限的规则或控制源 | 一项显式动作一个热区；默认不生成“开关待配置”占位卡 |
| 页面入口 | 目标页面、中文名称 | 整项就是单一入口，不再嵌套按钮或父级重复事件 |
| 系统控件 | 亮度、息屏时间、立即息屏、提示音偏好等 | 按能力选择；重启属于可选且需确认的维护操作 |

“心知天气”拖入后就在组件属性中填写 Key 和城市，保存后自动获取。再添加同类组件复用同一个现有天气资源，界面说明“与其他天气组件共用”，不要求用户重复输入密钥，也不引入多账号/多城市系统。旧配置有多个来源时，迁移前列出引用并选择保留来源，不静默删除仍被规则使用的数据。

删除天气组件只删除显示引用；不能连带删除其他组件/规则使用的服务配置或密钥。Key 留空表示保留，清除采用明确操作；未保存的天气参数不能被“更新天气”误当作已生效。刷新按钮仅在参数已保存、网络支持且限频允许时使用。

心知天气使用固定实况接口 `/v3/weather/now.json`、简体中文和摄氏度，位置支持服务商接受的格式并提供简短示例。只展示响应实际提供的城市、天气、气温和更新时间；缺失湿度不能补 0，也不能用室内传感器湿度冒充室外湿度。页面切换只读取共享缓存，手动刷新沿用至少五分钟限频；新组件在参数有效并保存前不发请求，已有服务保留启用状态。过期阈值由天气刷新周期推导并测试，不改变传感器鲜度阈值。接口与账号权限实施时核对[心知天气实况文档](https://docs.seniverse.com/api/weather/now.html)。

历史设置以趋势组件属性中的来源与记录摘要为主，保留一个按需进入的共享记录管理入口；取消屏幕页面上的独立保存按钮。历史服务继续允许无屏设备使用，删除趋势组件不会删除其他消费者使用的记录。

### 3.3 全局设置与实体生效

全局设置只放显示设备、主题/背景、默认首页与底栏、默认亮度、自动息屏、触摸提示音、控制确认间隔和可选维护权限。天气放组件属性，历史放相关组件/共享管理，不回到全局长表单。

- 默认所有页面“继承全局”；用户切换为独立外观时标识覆盖来源，并提供“恢复继承”。首次迁移保留现有自定义样式。
- 编辑画布立即反映草稿主题；保存后核对持久化配置版本和运行时已应用版本。应用失败显示原因，不能只凭 HTTP 成功显示“已应用”。
- 全局外观覆盖深色、浅色、高对比度及现有背景。先保证文字、图标、按钮对比度，不增加影响 RGB 稳定性的动画或大图资源。
- 能力与权限分别说明：缺少硬件、驱动未就绪、功能裁剪、权限不足、引用失效使用不同提示。有效触摸唤醒必须由已就绪触摸后端确认，不能只看配置是否写过引脚。

### 3.4 实体触控布局和操作

默认页面按已配置能力生成：首页、趋势、电机、外设执行、系统。首页用时间/天气和主要数值建立清晰层级，减少与底栏重复的跳转卡；缺少来源时用简洁说明，不伪造数值或默认塞入无用控件。字体、边距、圆角、图标与状态颜色统一，减少重复标题和“按钮套卡片”的视觉堆叠。

- 480×480 基线底部保留 72 px 五项导航；每项图标加短中文标题，整项可点。五页以内全部直达；更多页面采用四个入口加“更多”，首页始终可达。用户可在 Web 排序及选择入口，未列入底栏的页面仍能通过更多/滑动到达。
- 不同尺寸和旋转按能力调整布局并限制最小热区；不能在物理空间不足时机械压缩五个按钮。Web CSS 尺寸与实体像素尺寸分别验收。
- 图表、天气、数据和控制组件外框不响应动作。按钮仅在按下和抬起同一目标、未超过移动阈值时执行一次；横向滑动取消按钮候选；滑块捕获拖动且不翻页。
- 息屏时显示恢复说明应出现在操作前的帮助中；第一次完整触摸只唤醒，抬手后才能执行操作。唤醒不触发电机、导航或蜂鸣。
- 系统页采用清晰的设置行：亮度滑块及百分比、自动息屏选择、提示音开关、独立“立即息屏”按钮；维护信息折叠，重启默认不作为主要操作。不存在卡片容器与子按钮双重动作。
- 趋势直接展示刻度、单位、起止时间和“16:40 · 20.0 ℃”这类最新样本详情；实体点击图表不执行操作，滑动用于翻页。断采不补零且有断线/过期提示；无时钟时显示相对时间。
- 电机页突出实际状态、设定速度、脉冲与“正转 / 停止 / 反转”。参数修改不启动；首次或闲置后执行正/反转显示一次摘要确认，默认 60 秒、可配置 15–600 秒；停止免确认且优先。无反馈时只说明命令已发送，不显示未经确认的运行状态。

### 3.5 提示音和音量的通用配置

屏幕全局设置提供触摸提示音开关；有效按钮和导航完成后短鸣，滑动、普通卡片空白、唤醒及立即息屏保持静音。外设配置中的 `touchBuzzerDurationMs` 保留并修复生效，范围继续有上限。

驱动声明是否支持音量：有真实幅度/PWM/音频能力时，在对应外设配置中提供音量；当前布尔蜂鸣器仅显示“固定音量”，隐藏不可用的音量滑块。屏幕给出参数位置和只读摘要，不复制另一份硬件设置。外设执行若调用提示音，复用同一有时限的驱动动作及调度，不能绕过关闭保护或制造冲突。

### 3.6 外设配置与执行弹窗

诊断工具对接线、串口收发和 I2C 排查有价值，保留在“更多 → 诊断”，不占主操作区。读取状态和写入/发送使用原有权限边界，写操作继续受开发者模式等现有保护；不能为了隐藏按钮而额外阻断原本允许的只读诊断。共享 Modbus/I2C 总线的占用提示和冲突保护保留。

“数据与屏幕”合并卡片采用以下 2×2 布局，窄屏单列：

| 左列 | 右列 |
| --- | --- |
| 执行后上报数据 | 保留最近 10 条记录 |
| 允许设备屏幕控制 | 管理最近记录 |

三项分别控制平台上报、可记录数值历史、屏幕调用权限，不合并成一个总开关。管理按钮用于来源和记录范围，不是立即执行或保存规则；进入和返回必须保留当前编辑草稿。默认名称、类型和系统生成标签使用中文，稳定 ID 和用户自定义名称保持不变。

### 3.7 配置归属与兼容边界

外设配置提供硬件能力，外设执行提供数据与受限动作，设备屏幕保存布局与稳定引用。屏幕配置使用 `/config/screen_panel.json`；外设与执行规则分别使用 `/config/peripherals.json`、`/config/periph_exec.json`；天气和历史复用现有管理器及存储，不为每个组件复制文件。写入沿用 `ConfigStorage` 等现有受控入口，Web 不整体覆盖协议配置来保存天气。

| 配置归属 | 主要字段/内容 | 约束 |
| --- | --- | --- |
| 屏幕全局 | `homePageId`、`bottomNavPageIds`、`brightnessPercent`、`idleSleepSeconds`、`touchBeepEnabled`、`controlConfirmIdleSeconds`、主题/背景 | 沿用现有字段，前后端含义一致；默认亮度 70、息屏 120 秒、确认间隔 60 秒作为新配置建议值，既有有效值保留 |
| 页面/组件 | 稳定 ID、来源、布局、可选外观覆盖 | 缺导航字段从有效页面推导；无对应能力不生成假控件；限制由 API 能力目录提供，现有 8 页/24 卡/每源 10 点仅作基线 |
| 显示外设/后端 | 引脚、驱动、极性、最低可见输出、蜂鸣器时长/音量能力 | 不复制进卡片；按真实能力配置；逻辑 0 保持最低可见语义，不迁移成 sleep |
| 天气/历史服务 | 凭据、城市、更新周期、共享记录来源 | 同一资源共享；历史 allowlist 按变更合并，不能用屏幕选项覆盖其他功能的记录来源 |

自动息屏提供不息屏、30 秒、1/2/5/10 分钟等常用选项，保留已有合法自定义值；拖动或按键过程中不能自动息屏。触屏修改持久化后，Web 再读取能看到当前值；存在未保存 Web 草稿时提示版本变化，不自动覆盖草稿。

移除附加 MQTT 远程通道不影响主 MQTT 连接、FastBee 上报/订阅和其他协议功能。升级前扫描旧通道、来源和动作引用；仍引用退役动作的规则整体暂停并列出原因，保留原内容，不能跳过旧动作后继续执行剩余动作。旧枚举编号不复用成另一种动作，旧 API 明确拒绝重新启用退役通道、预报、自定义 URL 等能力。是否还存在相关旧入口和运行分支需回归确认，不将此处约束记为已完成。

## 八、发布与回退要求

首个实物验收参考 Waveshare ESP32-S3-Touch-LCD-4 Rev4，480×480。历史 MAC 为 `E8:3D:C1:F7:65:44`，串口曾在 COM8/COM9 间变化，IP 曾为 `192.168.5.47`；这些不是本轮确认的在线地址，发布前重新识别，不能仅凭 COM 号选择设备。其他非触屏设备及已转移到其他会话的光电传感器/继电器联动不属于本计划。

发布流程在审核后实施，使用仓库现有配置保留与构建锁工具；具体参数由目标、分区和配套 RGB SDK 决定：

1. 冻结源码和匹配的固件/Web 产物摘要；检查专用 RGB 构建配置，而非仅运行普通 S3 环境就视为等价。
2. 备份现场配置并使用私有保留/合并路径，保护设备身份、Wi-Fi、MQTT、用户和规则。先验证目标 MAC、Flash/分区布局、活动槽及产物兼容。
3. 使用 `scripts/firmware-build-lock.ps1` 和现有部署工具的 dry-run / build-only 能力检查，串行完成正式写入。Web 更新按目标文件系统保留流程处理，不能用空样例覆盖现场配置。
4. 为当前产物取得 `written=true`、`verified=true` 或对应 OTA 写入校验记录，再进行登录、资源版本、API、配置和运行状态读回。401 仅说明接口需要鉴权，不能单独据此认定设备不可访问。
5. 按第七章完成真实触摸、亮度、提示音、电机、天气和卷边验收；长期测试另起记录。失败时保留日志和配置，不盲目重刷。

回退保留成套固件/Web、原配置备份及可兼容的迁移版本；存在已知亮度、常鸣或重复动作问题的旧版本不能直接当作安全回退点。无法安全回退时禁用受影响动作并保留诊断入口。删除旧文档中的通用 `uploadfs`、未匹配配置的 `upload` 和工厂镜像从地址 0 强刷作为日常排障方案，避免破坏现场配置与分区。
